# wxhl-cygf 创意工坊 · UI 与内容结构整改（包格式 @2）

日期：2026-10-11
状态：设计已与用户逐条确认（分类/导航/卡片四要素/各类型字段/事件并行控制器/封面走 URL/世界书导入并进正式代码）

## 1. 背景与目标

一期上线后（https://cygf.657868.xyz），用户提出整改：

1. **分类要提级**：一期只有 `extension/build/character` 三类，且"同人角色"名不副实。改为 **5 个并列顶级分类**，顶部一排导航按钮（废弃右上角下拉框）。
2. **卡片信息要够**：每条内容在主页面必须展示 **封面图/头像 + 名字 + 简介 + 上传者**。
3. **上传要清楚**：一期上传太含糊；且**无法上传已经写好的世界书**。要按类型给专属表单，并支持「从酒馆导出的世界书 JSON」一键导入（有人已写好补丁，把它的逻辑并进正式代码）。
4. **载荷要对齐主卡**：构筑不要属性数值只要分配方向；人物改叫「人设」；新增「副本」「事件」「机制拓展」三个并列类型。

## 2. 分类体系（包格式 @2）

`format` 升级为 **`wxhl-mod@2`**（一期注册表为空、未对外发布，不做向后兼容）。

| type | 显示名 | 徽章色 | 内容形态 |
|---|---|---|---|
| `dungeon` | 副本 | 血红 | 结构化字段 → 渲染成世界书条目 |
| `event` | 事件 | 琥珀 | 世界书条目集合（含自带 EJS 控制器） |
| `mechanism` | 机制拓展 | 青蓝 | 世界书条目集合（= 一期的扩展包） |
| `build` | 构筑 | 紫 | 结构化字段 → 渲染成条目 |
| `persona` | 人设 | 金 | 结构化字段 → 渲染成条目 |

顶部导航：`全部 | 副本 | 事件 | 机制拓展 | 构筑 | 人设`。**列表与上传都按这五类分流。**

## 3. 公共外壳（manifest）

```jsonc
{
  "format": "wxhl-mod@2",
  "id": "abc12345",
  "name": "雾中列车",
  "type": "dungeon",
  "version": "1.0.0",
  "author": { "name": "作者名", "discord": "" },
  "tags": ["副本"],
  "description": "一句话简介（列表卡片显示）",
  "cover": "https://…/cover.png",   // 封面图/头像 URL；留空则页面用主题占位图
  "requires": { "cardVersion": "" }
}
```

- `cover`：URL 字符串，允许空。**一期不做图床**（玩家自己粘图链）。校验：`https?://` 开头、长度 ≤ 500、不含引号/尖括号/空白（防注入）。
- 卡片四要素 = `cover` + `name` + `description` + `author.name`。**这四项都是必填**（`description` 至少 1 字，`cover` 可空但仍占位）。

## 4. 各类型载荷

### 4.1 `dungeon` 副本

按主卡变量结构的「当前副本元数据 + 当前副本任务」形状：

```jsonc
{
  "副本名称": "雾中列车",
  "副本类型": "和平 | 阵营 | 血腥",
  "基准等级": 3,
  "时间限制": "三天",
  "背景设定": "…",          // 世界背景、起因
  "地图与区域": "…",        // 场景/区域/关键地点
  "敌人配置": "…",          // 敌人种类、强度、出现条件
  "主线任务": { "名称": "", "说明": "", "奖励": "" },
  "支线任务": [{ "名称": "", "说明": "", "奖励": "" }],
  "世界事件": [{ "名称": "", "说明": "", "奖励": "" }],
  "隐藏任务": [{ "名称": "", "说明": "", "奖励": "" }],
  "成就":     [{ "名称": "", "说明": "", "难度": "", "奖励": "" }],
  "GM指导": "…",            // 主持话术、判定口径、节奏与禁忌
  "额外条目": [ /* 可选的世界书条目，字段同 4.3 */ ]
}
```

渲染：1 条绿灯条目（名 `[回廊mod][副本]<包名>`，关键词 = 副本名称）+ `额外条目` 各 1 条。

### 4.2 `event` 事件

```jsonc
{
  "事件条目": [ /* 世界书条目，字段同 4.3；名字须以 事件_ 开头 */ ],
  "控制器条目": { "名称": "EJS/<包名>控制器", "正文": "<% … getwi('事件_…') %>" }  // 可选
}
```

**并行控制器（已核实可行）**：副本生成时 `getCardWorldbookEntries()` 读角色卡的**主世界书 + 全部附加世界书 + 全局世界书**，而「无限回廊mod」是附加世界书，所以工坊条目天然在池子里；`findControllers` 是**并集**找控制器、`buildEventSection` 用 `Promise.all` **并行渲染所有控制器**。因此包自带控制器与主卡控制器并存、各自挑事件、合并成段。

- **命名规范**（防撞车）：事件条目名一律 `事件_<包名>_<事件名>`；控制器名 `EJS/<包名>控制器`。
- 校验：`event` 包的每个条目名必须 `事件_` 或 `EJS/` 开头（响亮拒绝）。
- 事件条目一律装成**绿灯**（关键词由作者写），保证不依赖控制器也能独立触发。

### 4.3 世界书条目（`event` / `mechanism` / `dungeon.额外条目` 共用）

沿用一期的 `ExtensionEntry` 字段（name/content/enabled/constant/keys/keysSecondary/position/depth/order/probability/sticky/cooldown/delay/preventRecursion/excludeRecursion）。**不改**。

### 4.4 `build` 构筑（去掉属性数值）

```jsonc
{
  "构筑名": "重装堡垒",
  "定位": "物理破坏配合高容错换血",
  "属性分配方向": { "主属性": "STR|AGI|CON|PER", "副属性": "STR|AGI|CON|PER|无" },  // 只给方向，不给数值
  "天赋": { "名称": "无", "品质": "无", "属性加成": "无", "效果": {} },
  "血统": { "名称": "无", "品质": "无", "属性加成": "无", "效果": {} },
  "称号": { "名称": "无", "效果": {} },
  "职业": {
    "名称": "无", "稀有度": "无",
    "职业特性": {}, "职业技能": {}, "传承技能": {},
    "转职树": { "名称": "无", "分支": {} }     // 默认基础职业
  },
  "通用技能": { "技能名": { /* 技能Schema */ } },
  "主要装备": { "主武器": {...}, "副武器": {...}, "头部": {...}, "躯干": {...}, "手部": {...}, "下装": {...}, "饰品": {...} },
  "背包建议": { "物品名": { "描述": "", "数量": 1 } }
}
```

技能/装备槽的子 schema **复用一期**（与主卡 `变量结构_特殊资源通用版.json` 对齐）。

### 4.5 `persona` 人设（原「同人角色」）

```jsonc
{
  "角色名": "雾中剑客",
  "性格": "…",
  "爱好": ["…"],
  "厌恶": ["…"],
  "背景故事": "…",
  "构筑方向": "…",                      // 自由文本，可空（粗浅写方向）
  "构筑": { /* 可选：完整 BuildPayload，粘贴合法 JSON 时填入 */ }
}
```

渲染：1 条绿灯条目（关键词 = 角色名），正文含人设五要素 +（若有）构筑方向或嵌构筑。

## 5. 页面（workshop.html 重做）

### 5.1 顶部导航
标题 + **一排并列分类按钮**（全部/副本/事件/机制拓展/构筑/人设）+ 搜索框 + 上传按钮。当前分类高亮。

### 5.2 卡片网格（四要素）
封面图（`cover`，空则主题占位图，`<img>` 的 src 由 DOM API 设置、失败回退占位）+ 名字 + 简介（两行截断）+ 上传者。右上角类型徽章。

### 5.3 详情
封面大图 + 完整简介 + 作者/版本/下载数 + **落地预览**（`packToWorldbookEntries(pack)` 的结果，让作者/玩家看到实际写入的条目）+ 安装/更新/卸载 + 已装版本对比。

### 5.4 上传重做
- 顶部选类型（五选一），下面**按类型换表单**
- **`event` / `mechanism` / `dungeon.额外条目` 共用条目编辑器**，顶部加一个「**从酒馆导出的世界书 JSON 导入**」文件选择器（并进正式代码的补丁逻辑）
  - 支持原生 `entries` 对象/数组；映射蓝绿灯、关键词、位置（前/后/指定深度）、概率、递归、粘滞/冷却/延迟、禁用状态
  - **不支持的设置（向量化、分组、预算豁免、独立扫描深度、大小写/整词、高级次关键词逻辑、非 system 深度角色、作者注释位置、生成类型…）整次拒绝并列出原因**，绝不静默丢弃
  - 单文件 ≤ 10MB、≤ 2000 条；编辑器每页渲染 20 条
  - 导入不覆盖已填的名称/作者
- `dungeon` 走专属结构化表单（4.1 的字段），底部仍可导入额外条目
- `build` / `persona` 走结构化表单（4.4 / 4.5 的字段），提供「粘贴 JSON 填充」入口
- 提交前轻量校验，服务端权威校验（共享 zod 契约）

## 10. 补充（2026-10-12，用户追加）

1. **构筑回到"能填具体数值"**：`属性基础`（STR/AGI/CON/PER 四个数值）保留，另外新增 `等级`（number）与 `阶位`（string，如 `一阶`）。`属性分配方向`（主/副）**保留**，页面按填入的数值自动推导。
2. **职业完整镜像新卡 schema**（用户 2026-10-12 提供的新版 `变量结构_特殊资源通用版 (1).json`）：
   `名称/稀有度/转职阶段/职业等级/PEXP_当前/PEXP_升级所需/主属性加成{属性,值}/副属性加成{属性,值}/`**`职业简介`**`/职业技能/职业特性/传承技能/转职树`。全字段带 default，便于粘贴变量时原样捕捉。
3. **参考文件更新**：`src/wxhl-cygf/变量结构_特殊资源通用版.json` 换成用户 2026-10-12 给的新版（唯一差异是 `职业简介` 及若干注释措辞）。
4. **构筑支持"从我的存档读取"**：宿主新增桥接动作 **`readContractor`**（**只读**，不进互斥队列），照小手机竞技场的 `extractContractSave`：
   - 读 `getVariables({type:'message', message_id: m})`（m 取最后一个 AI 楼层，取不到回退 `-1`），从 `stat_data.契约者` 按白名单 **`CONTRACT_SAVE_KEYS = ['头部','属性','衍生属性','职业','通用技能','装备']`** 摘字段，并重算 `属性.实际 = 基础 + 加成 + 自定义加成`；
   - 返回 `{ 契约者: <摘出的子树> }`；
   - **不含** 经济/背包/人际关系/副本经历/论坛档案/系统日志 —— 只回构筑字段（用户确认），避免把整个存档送到云端页面。
5. **构筑支持"粘贴 JSON 捕捉"**：页面纯函数 `parseBuildJson(text)` 接受四种输入形状并映射成 `BuildPayload`：
   - 完整变量：`{ stat_data: { 契约者: {...} } }`
   - `{ 契约者: {...} }`
   - 直接是契约者子树
   - 直接就是一份构筑载荷（含 `构筑名`/`定位` 等）
   映射规则：`等级 ← 头部.等级`、`阶位 ← 头部.阶位`、`属性基础 ← 属性.基础`、`天赋/血统/称号 ← 头部.*`、`职业/通用技能/装备 ← 同名键`；缺的字段走默认；无法识别时**响亮报错**（不静默产出空构筑）。

事件/机制拓展/副本三类不受本节影响。
