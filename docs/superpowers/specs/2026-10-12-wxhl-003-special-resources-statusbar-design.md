# 小手机 · 状态栏特殊资源与职业区改造（设计）

- 日期：2026-10-12
- 范围：`src/wxhl-003`（小手机），本轮**只做状态栏**
- 上游：角色卡上传包 8.3（对方产物）的能力对齐；对方无源码，本设计以他的「项目说明」为功能清单、以产物中未压缩的渲染函数为行为参照，在本仓库的源码里重新实现
- 权威变量结构：`src/wxhl-003/变量结构_特殊资源通用版.json`（用户提供，本轮引入）

## 一、背景与目标

对方 8.3 引入了三样我们还没有的东西：一个**通用的「特殊资源」池**（新资源不必再为它改前端固定栏位）、**结构化的特殊状态**、以及**职业简介 / 可嵌套的职业特性**。本仓库的状态栏要能读懂并展示它们。

要解决的问题很具体：现在每加一种职业资源，就得在状态栏里改一套固定栏位；特殊状态的值一旦是对象，会直接渲染成 `[object Object]`。

### 目标

1. 状态栏读懂新变量结构。
2. **通用特殊资源面板**：按来源分组、任意层级递归折叠，挂到个人面板 + 小队成员 + 其他契约者 + 副本角色四处。
3. **特殊状态结构化展示**：`增益 / 减益 / 其他` 标签 + 说明 / 来源 / 持续时间 / 层数；旧字符串格式照常显示。
4. **职业区改造**：职业简介 + 职业特性（递归分组）+ 职业技能 / 传承技能（折叠）；个人面板与实体卡片**共用一套渲染**。

### 非目标（本轮明确不做）

- 论坛的四件事（本地存档 / 发帖身份 / 全论坛去重 / 回复时间递增）—— 第二轮单独出 spec。
- 世界书改动（用户已自行处理）。
- 写 MVU 的「论坛档案」（因果账本）—— 已取消，论坛数据只进浏览器本地存储。
- 旧 `职业.职业资源` 字段的兼容显示 —— 已定：**只读新结构 `特殊资源`**。
- 「职业目录」字段 —— 已从变量结构中移除，改为字符串 `职业简介`。

## 二、变量结构

新增 `src/wxhl-003/变量结构_特殊资源通用版.json`：用户给的脚本 JSON 原样复制，作为**主卡权威结构、只读副本**（与 `src/wxhl-cygf/变量结构_特殊资源通用版.json` 同一先例，见 `src/wxhl-cygf/README.md:33`）。

状态栏本轮要用到的字段：

| 路径 | 形状 | 用途 |
|---|---|---|
| `契约者.特殊资源` / `<实体>.特殊资源` | `record(string, any)` | 资源面板；一级 key = 来源（职业/装备/血统/天赋/技能/其他） |
| `<实体>.状态.特殊状态.<名>` | `string` 或 `object` | 状态面板；对象含 `分类 / 说明 / 来源 / 持续时间 / 层数`，可扩展 |
| `契约者.职业.职业简介` | `string` | 职业区一行文本 |
| `契约者.职业.职业特性` | `record(string, string \| record)` | 可嵌套分组，需递归 |

注意 `特殊资源` 的条目**不预设字段清单**——`当前 / 上限 / 单位 / 说明 / 来源 / 恢复方式` 只是"消耗型条目的建议字段"，其余自定义字段也要能显示。

## 三、设计

### 3.1 渲染架构

现状：状态栏是**静态模板 + jQuery 填空**（`statusbar/core.ts` 的 `mountStatusbar` → `template.html` 提供固定 `id` 骨架 → `populateCharacterData()` 用 `$c.find('#id').html(...)` 填充）；列表类内容由 JS 拼 HTML 字符串注入。

本轮新增 `src/wxhl-003/statusbar/render.ts`，放**纯函数渲染器**：

- 零 jQuery / 零 DOM 依赖，只吃 `(data, basePath, ...)`、吐 HTML 字符串
- 于是可以直接单测（仓库现有测试全是纯函数风格，不开 DOM 环境）
- core.ts 的个人面板与实体卡片**都调它**，消除现在"个人一套、实体一套"的重复

折叠沿用既有的 `mate-sub` 机制：`data-sub-key` 做键 + `expand_subs` Set 存状态（`core.ts:152` `toggleMateSub`、`core.ts:181-187` 应用状态）。**不用** group/section 那套 —— 它们的键是「标题文本」（`core.ts:132/139`），动态生成同名分组会撞键。

生成的 HTML **自带** `collapsed` / `hidden` class（未展开时），与现有 `renderEntityCard` 的写法一致（`core.ts:1386-1396`）；其后统一由 `applyUiStateToDom()` 套状态（`core.ts:2440`）。

可编辑字段沿用现成的 `editSpan`（`core.ts:190`，数字）与 `editText`（`core.ts:193`，文本）—— 都是纯字符串函数。

**但要把它们抽出来**：这三个小工具（`escapeAttr` `core.ts:69`、`editSpan`、`editText`）现在都定义在 `core.ts` 内部。若 `render.ts` 直接从 `core.ts` 导入，而 `core.ts` 又要导入 `render.ts`，就成环。故新增 `statusbar/editable.ts` 承载这三个函数，`core.ts` 与 `render.ts` 都从它导入。这是本轮对既有代码唯一的结构性改动。

### 3.2 特殊资源面板

```ts
renderResourceTree(data, basePath, expanded: Set<string>, keyBase: string): string
```

`data` 即某个 `特殊资源` 对象。判定规则（自上而下）：

| 值的形状 | 渲染 |
|---|---|
| 对象且含 `当前` 或 `上限` | **条目叶子**：`名称　当前 / 上限 单位`；`当前` 缺失显示「未记录」 |
| 数组 | **折叠块**，标题 `名称 (N)`，逐项递归 |
| 对象且含嵌套对象/数组 | **分组折叠块**，标题 `名称 (N)`，逐键递归 |
| 对象（其余） | 叶子：逐字段 `键：值` |
| 标量（非空） | 一行 `名称：值` |
| `null` / `undefined` / `''` | 跳过 |

- 根节点标题「资源列表 (N)」，无内容显示「暂无资源」
- 折叠键 = `keyBase + '.' + 数据路径`，**唯一**（用数据路径而非标题，避免同名分组撞键）
- 条目内部字段全部可编辑（见 3.5）

**挂载点（4 处）**

1. **个人面板**：`template.html:276-280` 的 `特殊状态` sub-section **之后**，加一块同级的 `特殊资源` sub-section（`<div id="state-resources">`）；在 `core.ts:1898` 那段填充逻辑旁填充。
2. **小队成员 / 其他契约者 / 副本角色**：三者在 `renderEntityCard`（`core.ts:943`）里共用一套代码，在 `mate-sub` 序列（属性 / 职业 / 通用技能 / 装备 / 背包，`core.ts:1189-1432`）末尾追加一块 `特殊资源`，键沿用 `escapeAttr(subKeyBase + '.特殊资源')` 的前缀模式（`core.ts:1189-1193`）。

**旧字段**：不读 `职业.职业资源`。

### 3.3 特殊状态

```ts
renderSpecialStatusList(states, basePath): string
```

替换现在两处近乎重复的实现：个人面板 `core.ts:1898-1912`、实体卡片 `core.ts:1434-1448`。

每条渲染为：

```text
[标签] 状态名  说明文字  [N层]  持续：…  来源：…
```

- **分类 → 标签**：读 `分类`（兼容 `类型`），先做**同义词归一**（含「增益/强化/buff」→ 增益；含「减益/负面/debuff」→ 减益），其余归「其他」；配色复用 `tag-green / tag-red / tag-gray`
- `说明` 兼容 `描述` / `效果` 两种旧写法
- `层数` 有值才显示；`持续时间` / `来源` 有值才显示
- **旧字符串格式**：原样显示，标签归「其他」
- 空值跳过；一条都没有显示「无」

这一项顺带修掉：现在值若是对象会被 `editText` 的 `(val + '')` 渲染成 `[object Object]`（`core.ts:194`）。

### 3.4 职业区

```ts
renderCareerSection(career, basePath, expanded: Set<string>, keyBase: string): string
```

产出四块：

1. **职业简介** —— 一行文本，可编辑（`职业.职业简介`）
2. **职业特性** —— 值 `string` → 文本叶；值 `object` → 分组折叠块，递归（对应变量结构里"支持文字叶节点和嵌套分组"）
3. **职业技能** —— 折叠块，内容复用现有的 `renderSkillsHtml`（`core.ts:575`）
4. **传承技能** —— 同上

个人面板（`core.ts:1931-1979`）与实体卡片（`core.ts:1311-1371`）两处都改调它。个人面板的职业区骨架在 `template.html:292-327`（该 section 默认折叠），需要给「职业简介」加一个填充槽位。

### 3.5 交互：编辑、改名、删除

| 字段 | 控件 |
|---|---|
| `当前` / `上限` / `层数` | `editSpan`（点改数字） |
| `单位` / `说明` / `来源` / `持续时间` / 自定义字段 / 职业简介 | `editText`（失焦保存） |
| **资源名（键）** | `editText` + 特殊处理 |

**资源名（键）的处理**——键不是字段，改名要动结构：

- 改名：`_.unset(parent, 旧键)` + `_.set(parent, 新键, 值)`
- **清空**：删除该条资源
- 清空前**弹一次 `confirm()`**（与背包删除一致，`core.ts:2708-2714`），防手滑；如果确认不要这一步，实现时去掉即可
- 新键与兄弟键重名时：`alert()` 提示后**不执行改名**，避免静默覆盖（`core.ts` 现有反馈手段就是 `confirm` / `alert`，不引入 toastr）

这批编辑走现有的 `bindEditable()` 委托机制（`core.ts:528-556` → `saveVariable` / `saveVariableStr`），并照旧 `appendSystemLog` 记一笔。

### 3.6 错误处理

渲染器**不抛异常**：任何值形状不符预期，一律降级为该值的字符串形式或跳过该项，同时 `console.warn` 带路径。理由：状态栏是玩家随时打开的面板，一个畸形条目不该让整块面板白屏。

## 六、验收

1. `statusbarRender.test.ts` 全绿。
2. 全仓回归**不低于**基线：2418 通过 / 1 失败。
   - 那 1 个既有失败是 `cloudflare/wxhl-market/rank.test.js`（市场加了 `hasMore` 后旧断言未更新），**与本轮无关**，不在本轮范围内修。
3. 手动核对（在酒馆里跑）：个人面板能按来源折叠看到资源；对象型的特殊状态不再显示 `[object Object]`；三类实体卡片都有资源面板；点改数值/文本能写回变量。

## 七、风险与待确认

1. **特殊资源面板的落点**：按用户要求放在 `◆ 状态` section 内、与 `特殊状态` 平级相邻。语义上「资源」不属于「状态」，若后续觉得别扭，可提升为独立的 `◆ 特殊资源` section —— 结构上只是挪一层。
2. **清空名字即删除** 是不可逆操作，靠一次 `confirm()` 兜底；若玩家量大，后续可考虑改为"先标删除、二次确认"。
3. **改名会写结构**：资源键若有别名引用（世界书/AI 约定），改名会断开。世界书侧需注意。
4. 本轮不动 `core.ts` 的既有折叠机制，只新增 `mate-sub`；若后续 `mate-sub` 数量过多导致面板过长，再考虑分组收纳。
