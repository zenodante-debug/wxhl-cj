# wxhl-003 自由市场 · 设计文档

日期：2026-09-20
状态：已与用户对齐，待实现

## 1. 背景与目标

在 wxhl-003（无限回廊小手机）中新增**自由市场**：玩家把背包物品挂上全服市场，其他玩家用 UP 购买。模式学自九渊项目的寄售坊市（Cloudflare Worker + KV），但针对本项目做两点强化：

1. **价格强校验**：用户有「一大堆玩家」，不能自由出价。Worker 内置经济系统价格表，装备挂单按「品质/类型/阶位」计算合法价格区间，超价拒绝。
2. **对接主卡 MVU 变量**：结算直接读写 `契约者.经济.UP` 与 `契约者.背包`。

信任模型：上架即扣物、购买即扣款在**玩家本地**结算，服务器只记账挂货款，卖家随时领取。服务器无法校验卖家是否真有此物——熟人小圈子以信义为本，但价格由服务器硬校验兜底。

## 2. 总体架构

```
玩家酒馆(前端脚本 wxhl-003)            Cloudflare(用户自己的账号)
┌───────────────────┐   fetch/JSON   ┌──────────────────────┐
│ 手机桌面「自由市场」 │ ────────────► │ wxhl-market Worker   │
│ 逛市场/上架/我的    │ ◄──────────── │ + KV(挂单/货款挂账)   │
└────────┬──────────┘                └──────────────────────┘
         │ 本地结算(Mvu.getMvuData → _.set → replaceMvuData → 回读校验)
         ▼
MVU 变量: 契约者.经济.UP / 契约者.背包
```

- Worker 代码收进本仓库 `cloudflare/wxhl-market/worker.js`，版本可控。
- 部署到用户自己的 Cloudflare 账号，不复用九渊的 Worker/域名。
- 域名：用户已自购域名（审核中），到手后绑定；先用 `workers.dev` 跑通。

## 3. Worker 端设计

### 3.1 KV 存储结构

绑定变量名 `MARKET`：

| key | 内容 | TTL |
|---|---|---|
| `m:i:<15位毫秒时间戳>-<6位随机>` | 挂单 JSON | 30 天 |
| `m:pro:<client>` | 卖家待领货款（UP 字符串） | 无 |

挂单 id 定长时间戳的字典序即时间序，浏览按 key 升序扫描取尾部；售出/下架直接删除挂单键，扫描量恒小。

### 3.2 挂单数据结构

```json
{
  "id": "00001726944000000-a1b2c3",
  "client": "随机客户端标识(≤64)",
  "seller": "卖家角色名(≤24)",
  "tier": "卖家阶位, 如 三阶(≤12)",
  "kind": "equip | goods",
  "item": { "原始背包条目快照": "见 3.4" },
  "qty": 1,
  "price": 500,
  "created": 1726944000000
}
```

### 3.3 价格校验（核心）

内置一阶基准价表（来自经济系统文档）：

| 类型 | 白 | 蓝 | 金 | 紫 |
|---|---|---|---|---|
| 武器 | 30~60 | 100~200 | 400~800 | 1500~3000 |
| 防具 | 15~40 | 50~150 | 250~600 | 1000~2000 |
| 饰品 | 20~40 | 60~150 | 300~700 | 1200~2500 |

**参考价 = 一阶基准价 × 阶位系数**，x 阶系数 = x²（一阶×1、二阶×4、三阶×9、四阶×16、五阶×25）。

装备（`kind=equip`）校验规则：

| 品质 | 规则 |
|---|---|
| 白 | **拒绝上架**（经济系统：白装无市场） |
| 蓝 | `下限×0.4 ≤ price ≤ 上限×1.0`（平价禁溢价） |
| 金 | `下限×0.4 ≤ price ≤ 上限×1.5` |
| 紫 | `下限×0.4 ≤ price ≤ 上限×2.0` |
| 银 | **拒绝上架**（有价无市，只走剧情） |

- 下限 ×0.4 对应系统 40% 回收价：允许贱卖，不许离谱。
- `类型` 只认 武器/防具/饰品；装备物品缺 `品质` 或 `类型` 字段 → 拒绝（数据不完整，无法定价）。
- 物品缺 `阶位` → 按卖家当前阶位计算（前端在表单中明示）。

普通物品（`kind=goods`，消耗品/特殊道具）自由出价，仅防刷：

- `qty` 整数 1~99；`price` 0~9,999,999；名称 ≤40 字符；描述 ≤200 字符。

**v1 明确不计入定价的因素**：装备强化等级、主副属性加成。+5 紫武也只能按基础区间挂，后续版本再扩展。

校验逻辑抽成纯函数 `checkPrice(kind, item, sellerTier, price)`，返回 `{ ok, min, max, reason }`，前后端共用同一份表（Worker 内置副本 + 前端用于表单提示；以 Worker 为准）。

### 3.4 装备物品快照

背包条目为 `record<物品名, {描述, 数量, ...任意装备字段}>`。挂单时快照整条条目（装备含 品质/类型/阶位/伤害骰/防御/加成/强化等级 等字段），JSON ≤ 2KB。买家购入后整条放回背包，字段不丢失。

### 3.5 接口

| 方法/路径 | 请求体 | 响应 | 说明 |
|---|---|---|---|
| POST `/market/list` | `{client, seller, tier, kind, item, qty, price}` | `{id}` / 4xx | 上架；先过 3.3 校验 |
| GET `/market/listings` | — | `{listings: [最新50条]}` | `Cache-Control: no-store` |
| POST `/market/buy` | `{id, buyer, client}` | `{ok}` / 404 / 403 | 给卖家 `m:pro` 挂账后删挂单；禁止买自己的单 |
| POST `/market/cancel` | `{id, client}` | `{ok}` / 404 / 403 | 卖家下架取回 |
| POST `/market/collect` | `{client}` | `{gained}` | 领取全部挂账（读后清零） |
| GET `/market/mine?client=` | — | `{pending, listings}` | 我的货款 + 我的在售单 |

CORS 全开（`Access-Control-Allow-Origin: *`），与九渊一致。所有入参做长度/数值上限校验防写爆 KV。已知并接受：KV 无原子判重，极小概率双买同一单会双计货款，小圈子可接受。

## 4. 前端设计（src/wxhl-003）

### 4.1 入口

手机桌面 app-grid 新增「自由市场」图标（天平/摊位造型 svg），点击切换到市场视图，与回廊论坛、PvP竞技场平级。

### 4.2 三个页签

- **逛市场**：最新 50 单卡片（物品名/品质/阶位/数量/单价/卖家/上架时间），品质筛选；购买 → 确认框 → 本地结算 → 服务器销账。
- **上架**：从背包选物品（数量>0）→ 自动识别 kind 并带出品质/类型/阶位 → 装备显示合法价格区间提示（如「蓝·武器·二阶：400~800 UP」）→ 填价提交 → 本地扣背包数量。
- **我的**：我的挂单列表（可下架取回）+ 待领货款（一键领取入 UP）。

### 4.3 代码结构

- `src/wxhl-003/market/api.ts`：fetch 封装，`MARKET_API` 常量（部署域名，可改）。
- `src/wxhl-003/market/priceTable.ts`：价格表 + `checkPrice` 纯函数（与 Worker 同规则），供上架表单实时提示。
- `src/wxhl-003/market/settle.ts`：MVU 本地结算（见 4.4），纯逻辑可单测。
- `src/wxhl-003/market/MarketView.vue`：市场界面。
- `store.ts` 挂 market 状态（listings/pending/loading）；client id 持久化在 localStorage（如 `wxhl003_market_client`，首次随机生成）。

### 4.4 本地结算（复用现有模式）

一律走 `Mvu.getMvuData({type:'message', message_id:'latest'}) → _.set → Mvu.replaceMvuData → 回读校验`，与副本结算同一套：

- **上架**：`背包[物品名].数量 -= qty`（归零条目被 schema transform 自动清除）
- **购买**：先查 `经济.UP ≥ price`，`经济.UP -= price`；`背包[物品名]` 存在则 `数量 += qty`，否则以快照整条入包
- **下架**：快照整条回背包（同名合并数量）
- **领取**：`经济.UP += gained`

**失败回滚原则**：先改本地变量再调服务器，服务器返回失败则逆向回滚（加回数量/加回 UP），保证「服务器没记账、本地就不动」。回读校验失败时按现有惯例 toastr 警告（变量已落档但未核对上）。

## 5. 部署计划

1. 仓库内写 Worker（`cloudflare/wxhl-market/`），Cloudflare MCP/wrangler 建 KV 命名空间并绑定变量名 `MARKET`。
2. 部署到 `wxhl-market.<账号>.workers.dev`，冒烟测试六个接口。
3. 用户国内直连验证；不通则等域名审核完成后绑自定义域名（代码零改动，只改绑定）。
4. 前端 `MARKET_API` 指向最终域名。

## 6. 测试

- `cloudflare/wxhl-market/` 侧：`checkPrice` 单测覆盖全品质×类型×阶位边界（下限 0.4 倍、溢价上限、白/银拒绝、缺字段拒绝、缺阶位回退卖家阶位）。
- 前端 `__tests__/market.test.ts`：settle 纯逻辑（上架扣减、购买合并同名、下架回包、UP 扣/加、余额不足拒绝、回滚）。
- 手动冒烟：部署后 curl 六接口；酒馆内完整走一遍 上架→购买→领取→下架。

## 7. 明确不做（YAGNI）

- 以物易物 / 装备+补差价（留给论坛扮演）
- RP 交易（RP 是荣誉货币，不进市场）
- 强化等级计入定价（v2）
- 消耗品白名单校验（方案 B，后续可无缝升级）
- 原子交易/Durable Objects（小圈子不需要）
