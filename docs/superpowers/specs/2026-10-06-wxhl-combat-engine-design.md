## 1. 定位与目标

### 1.1 这个脚本做什么

把无限回廊世界书 8.2 的战斗系统**从正文 AI 手里完全抽出来**，做成一个独立的前端脚本：

- **数值结算归引擎**：掷骰、命中、伤害、状态、资源，全部由真随机 + 确定性公式计算
- **战术决策归敌方 AI**：每个敌人的行动意图由配置的 AI 决定（以杀死玩家为目的的最优解）
- **叙事归收尾 AI**：战斗结束后由 AI 把战报写成正文，写回聊天记录
- **玩家操作归 UI**：玩家在全屏覆盖层里填行动槽、选择反应动作

**正文 AI 不再参与战斗的任何数值环节**。它只看到战斗结束后的战报。

### 1.2 为什么要做

| 现在（正文 AI 战斗） | 目标（引擎战斗） |
|---|---|
| AI 心算公式，经常算错 | 引擎跑公式，永不算错 |
| AI 从预埋骰池取骰，可能被篡改 | 引擎用 `crypto.getRandomValues` 真随机 |
| 一场战斗要十几楼正文，等很久 | 战斗在覆盖层里闭环，只落一条收尾楼 |
| 玩家效果写"无视xx"AI 就直接生效 | 引擎一律过 `<规则系能力判定>` |
| 战斗状态散落在正文里，刷新就乱 | 战斗状态结构化存脚本变量，可回放 |

### 1.3 不在本脚本范围内

- 副本生成、敌人生成（wxhl-003 已做）
- 市场、工坊、排行榜（wxhl-003 已做）
- 状态栏显示（wxhl-003 statusbar 已做）
- 副本结算（wxhl-003 settlement 已做）

本脚本**只做战斗**。战斗结束后把 HP/MP/耐力/状态/掉落写回 MVU 变量，其他系统照常工作。

### 2.3 回合状态机

引擎本体是**纯函数状态机**，不是命令式 async 流程。

```ts
type 战斗事件 =
  | { 类: '开始回合' }
  | { 类: '进入单位'; id: string }
  | { 类: '声明行动'; id: string; 行动: 行动声明 }
  | { 类: '玩家决策'; 选择: any }        // ← 从暂停点回来
  | { 类: '结束回合' };

type 待决点 =
  | { 类: '打断'; 攻方: string; 守方: string; 技能: 战斗解释 }   // 阶段B1b
  | { 类: '防御'; 攻方: string; 守方: string; 伤害: number }     // 阶段B2
  | { 类: '转阶段'; id: string; 阈值: string }                   // 阶段D
  | { 类: '濒死'; id: string; 已成功: number; 已失败: number };   // 阶段F

// 引擎本体
function 推进(状态: 战斗状态, 事件: 战斗事件): {
  状态: 战斗状态;
  步骤: 结算步骤[];
}
```

**为什么用状态机不用 async 流程：**

- 玩家选了「关键时刻暂停弹反应」，命令式 `await 弹窗()` 会把结算逻辑切成碎片
- 状态机让 `(状态, 事件) → 新状态` 变成纯函数，结算可以先跑出一整条步骤流
- UI 逐个播步骤，遇到待决点就停下来问，问完把答案作为事件喂回去继续
- **整场战斗可回放、可单测、可存档** —— 存档就是一个 `战斗状态` 对象

## 3. 数值权威与防火墙

### 3.1 数值权威链

```
┌─────────────────────────────────────┐
│  所有效果（敌我一视同仁）              │
│                                     │
│  普通效果 → 走触发/条件/动作解释器     │
│                                     │
│  规则系效果 → 一律过 <规则系能力判定>  │
│    判定值 = 1d20 + 关联属性修正        │
│    vs                                  │
│    对抗目标 = (基础DC + 目标属性修正)   │
│            × 类型系数                 │
│                                     │
│  过了 → 生效                          │
│  没过 → 当没这条，正常结算             │
│                                     │
│  托管效果 → AI 返回操作 → 引擎校验    │
│    校验不过 → 当没发生                 │
└─────────────────────────────────────┘
```

**没有例外。没有"玩家特殊待遇"。没有"这个太强了直接生效"。**

### 3.2 防火墙规则

**无论装备/技能效果里写的多么花里胡哨** —— "无视一切"、"最高优先级"、"必定命中"、"无法闪避"、"即死"、"无敌" —— **全部当违规的、开挂的**。

引擎碰到规则系词条，**一律**按世界书 `<规则系能力判定>` 跑对抗：

```ts
判定值 = 1d20 + 关联属性修正
对抗目标 = (基础DC + 目标属性修正) × 类型系数 + 目标属性修正
```

- 判定值 ≥ 对抗目标 → 效果成功
- 判定值 < 对抗目标 → 效果无效，正常结算

**基础DC表**（世界书原文）：

| 目标位阶 | 基础DC |
|---|---|
| 1阶 | 35 |
| 2阶 | 140 |
| 3阶 | 420 |
| 4阶 | 980 |
| 5阶 | 1925 |

**类型系数**：杂兵 0.6 | 精英 0.9 | BOSS 1.2 | 隐藏BOSS 1.5 | 契约者 1

**例子：B·元素陨灭弹的「元素湮灭穿透」**

原文写：「此弹命中时，无视目标一切神秘侧防御、护盾、阵地、加护、免疫与防御型被动效果。此穿透具有最高优先级」

引擎处理：
1. 命中判定过了
2. 发现词条「穿透」→ 触发 `<规则系能力判定>`
3. 判定值 = 1d20 + PER修正 vs 对抗目标 = (基础DC + 目标属性修正) × 类型系数
4. **过了** → 跳过防御/护盾/免疫，直接进伤害结算
5. **没过** → 正常吃防御/护盾，跟普通攻击一样

**这条规则敌我一视同仁。** 玩家拿了"必中一击"也要过判定，敌人拿了"无敌护盾"也要过判定。

### 3.3 词条与规则系效果的区分

**词条**（如「不可被常规攻击命中」「禁止位移」）是**状态标签**，不是规则系效果：
- 不需要过判定
- 只是描述单位的某种特性
- 引擎在读词条时直接检查（`单位.词条.has('不可被常规攻击命中')`）

**规则系效果**（如「穿透」「必中」「即死」「无敌」）是**判定触发的效果**：
- **必须**过 `<规则系能力判定>`
- 过了才生效，没过当没这条

**例子：终焉信标 vs B·元素陨灭弹**

- 终焉信标：「完全体状态下无法被常规地面攻击命中，仅可被对空技能或飞行单位攻击」→ 这是**词条**
- B·元素陨灭弹：「无视一切防御、护盾、免疫，最高优先级穿透」→ 这是**规则系效果**

这颗弹打终焉信标的完全体：
1. 终焉信标的词条「不可被常规攻击命中」：常规地面攻击打不中
2. 这颗弹不是"常规地面攻击"（是天基武器），所以**可以命中**
3. 但这颗弹的"穿透"是规则系效果，要过 `<规则系能力判定>`
4. 过了 → 无视终焉信标的护盾/防御
5. 没过 → 正常结算

**没有优先级层，没有"谁压谁"，只有"过了判定就生效，没过就不生效"。**

## 4. 战斗状态与持久化

### 4.1 战斗状态结构

```ts
interface 战斗状态 {
  进行中: boolean;
  回合: number;
  先攻: string[];                       // 单位 id，按先攻降序
  单位: Record<string, 战斗单位>;
  待决: 待决点 | null;                  // 非空 = 暂停中
}

interface 战斗单位 {
  id: string;        // 变量路径键：'契约者' | '小队.成员.白露露' | '副本角色.骨卫兵'
  阵营: '我方' | '敌方';
  类型: string;      // 杂兵/精英/BOSS/… → 决定 HP 系数与致命效果分层
  距离: number;      // 距玩家米数；-1 = 已脱离
  行动槽: { 主要: number; 次要: number; 移动: number; 反应: number; 免费: number };
  额度: number;      // 本回合剩余移动额度（米），每回合重置为【移动距离】
  冷却: Record<string, number>;         // 技能名 → 剩余回合
  护盾: number;
  架势: { 类型: string; 层数: number } | null;
  状态: 状态条目[];  // 流血/灼烧/破甲… 含层数与剩余回合
  濒死: { 成功: number; 失败: number } | null;
  资源: Record<string, number>;         // 任意命名资源（保存/充能/加护/冻结标记…）
  词条: Set<string>; // 标签（不可被常规攻击命中/禁位移/禁回复…）
}
```

### 4.2 持久化

**战斗状态存脚本变量**（`getVariables({type:'script', script_id})`），不动 MVU schema。

```ts
// 脚本变量
{
  战斗: 战斗状态
}

// MVU 变量（同步给状态栏）
契约者.衍生属性.HP_当前 / MP_当前 / 耐力_当前
契约者.状态.特殊状态
契约者.副本角色.骨卫兵.衍生属性.HP_当前
契约者.副本角色.骨卫兵.状态.特殊状态
```

**为什么分开存：**

- 战斗状态是**结构化的**（先攻/距离/槽/冷却/护盾/架势/资源/词条），MVU schema 里没有对应字段，硬塞会被 zod 剥掉
- HP/MP/耐力/特殊状态 是**MVU 已有的字段**，引擎写回后状态栏能同步显示
- 刷新页面后，脚本变量还在，战斗可以继续；MVU 变量也在，状态栏不会乱

**buff 的持久化见 §7。**

## 5. 战斗解释（一次性翻译）

### 5.1 为什么要一次性翻译

技能/装备/天赋/血统的效果是**自然语言文本**，引擎看不懂。但**不能每回合问 AI**（太慢）。

所以**每场战斗开始时**，把所有参战单位的技能/装备/天赋/血统/称号送到 AI，**一次性**翻译成结构化的「战斗解释」，**缓存整场战斗**。

之后每回合都是纯算术，不再调 AI。

### 5.2 战斗解释结构

```ts
interface 战斗解释 {
  // ① 直读字段 —— 技能自带，不用 AI
  行动消耗: string; 射程: string; 目标: string;
  消耗: string; 冷却: number; 分类: string; 类型: string; 可预判: boolean;

  // ② AI 翻译出的规则列表 —— 引擎按触发点跑
  规则: 规则[];

  // ③ 翻译不了的，原文留底 + 指定触发点，走托管
  托管: { 原文: string; 触发点: 触发点[] }[];
}

interface 规则 {
  触发: '常驻' | '进入战斗' | '回合开始' | '回合结束'
      | '攻击时' | '命中时' | '受击时' | '被命中后' | '击杀时' | '资源变化时';
  条件?: 条件;
  作用域: '自身' | '我方全体' | '敌方全体' | '攻击目标' | '命中点';
  优先级?: 0 | 1 | 2 | 3 | 4;   // 见 §3.3
  动作: 动作[];
}

type 取值 = { 源: '资源' | '属性' | '常数' | '层数' | '最终伤害' | '溢出伤害'; 名?: string; 系数?: number; 取整?: '下取整' };
type 条件 = { 左: 取值; 比较: '≥' | '>' | '≤' | '<' | '='; 右: 取值 };

type 动作 =
  | { 类: '资源'; 名: string; 操作: '获得' | '消耗' | '设为'; 量: 取值; 衰减?: 取值 }
  | { 类: '护盾'; 量: 取值 }
  | { 类: '数值修正'; 目标: '伤害' | '减伤' | '命中' | '闪避' | '反应动作' | '移动距离' | '攻击倍率' | '基础伤害骰' | '最大HP上限' | '全元素抗性'; 量: 取值; 不可净化?: boolean }
  | { 类: '施加状态'; 名: string; 持续: number; 层数?: 取值; 词条?: string[] }
  | { 类: '词条'; 名: string; 操作?: '附加' | '移除' }
  | { 类: '领域'; 名: string; 持续: number; 范围?: string; 规则: 规则[] }
  | { 类: '切换形态'; 到: string }
  | { 类: '追加攻击'; 次数: number }
  | { 类: '范围伤害'; 中心: string; 半径: number; 量: 取值 }
  | { 类: '条件分支'; 条件: 条件; 真: 动作[]; 假: 动作[] }
  | { 类: '规则系判定'; 效果: '穿透' | '必中' | '必暴' | '即死' | '无敌' | '锁血' | '无视'; 目标: string };  // 唯一入口
```

### 5.3 翻译流程

## 6. 规则解释器

### 6.1 解释器职责

引擎拿到战斗解释后，按触发点跑规则：

1. **收集触发点**：当前是「回合开始」，找出所有 `触发: '回合开始'` 的规则
2. **判定条件**：`条件` 非空则判定，不过则跳过
3. **判定作用域**：`我方全体` → 遍历我方所有单位
4. **执行动作**：按 `动作[]` 顺序执行

### 6.2 动作执行

| 动作类 | 引擎行为 |
|---|---|
| 资源 | 修改单位的 `资源` 表 |
| 护盾 | 修改单位的 `护盾` 值 |
| 数值修正 | 累加到对应字段（伤害/减伤/命中/闪避…） |
| 施加状态 | 往目标单位的 `状态` 数组加一条 |
| 词条 | 往目标单位的 `词条` 集合加/删一个标签 |
| 领域 | 在战场上创建一个领域对象，领域有自己的 `规则[]` |
| 切换形态 | 修改单位的 `形态` 字段（影响可用技能/攻击方式） |
| 追加攻击 | 在当前攻击结算后，再追加 N 次完全相同的攻击 |
| 范围伤害 | 对指定范围内的所有单位结算伤害 |
| 条件分支 | 判定条件，走 `真` 或 `假` 分支 |
| 规则系判定 | 走 `<规则系能力判定>`（见 §3.2） |

### 6.3 领域系统

**领域不挂在单位上，挂在战场的一个点上。**

```ts
interface 领域 {
  id: string;
  名: string;
  持续: number;
  中心: string | { x: number };   // 可以是单位 id，也可以是固定坐标
  范围?: string;                   // "半径15米"
  规则: 规则[];
}
```

每回合开始时，引擎检查所有领域：
1. 领域 `持续` 减 1，到 0 则移除
2. 对领域范围内的所有单位，跑领域的 `规则[]`

**例子：元素禁区**

```ts
{
  id: '领域_元素禁区_1',
  名: '元素禁区',
  持续: 5,
  中心: { x: 14 },        // 命中点在 14 米处
  范围: '半径15米',
  规则: [
    { 触发: '常驻', 作用域: '敌方全体',
      动作: [{ 类: '数值修正', 目标: '全元素抗性', 量: { 源: '常数', 系数: -0.5 } }] },
    { 触发: '常驻', 作用域: '敌方全体',
      动作: [{ 类: '词条', 名: '禁止位移/闪现/传送' }] }
  ]
}
```

每回合：
- 距离在 `[14-15, 14+15] = [-1, 29]` 米内的敌方单位，全元素抗性 -50%，禁止位移
- 持续 -1，到 0 时移除

### 6.4 托管

**托管是逃生舱，不是常规路径。**

翻译不了的效果进 `托管[]`，每个触发点问一次 AI：

```ts
interface 托管 {
  原文: string;
  触发点: 触发点[];
}
```

**例子：崩毁协议核心（终焉信标）**

```jsonc
{
  "原文": "终焉信标的攻击具有超强破坏性，攻击可向下穿透五公里大地。",
  "触发点": ["命中时"]
}
```

引擎碰到这个触发点时：
1. 调 AI：「这个效果现在该产生什么操作？」
2. AI 返回一组最小操作：
   ```json
   [ {"op":"环境叙事","内容":"攻击穿透五公里大地"} ]
   ```
3. 引擎校验：
   - 动得了的目标吗（在战场、不在友方受保护）
   - 数值在合法区间吗（别出现 -999999）
   - 操作总数有没有爆
4. 校验过 → 执行
5. 校验不过 → **整个托管效果跳过**，当没发生，绝不瞎猜

**限流**：每回合最多 1 次托管判定。超过的直接跳过。

## 7. buff 系统

### 7.1 buff 存哪

**所有 buff（增益/减益/状态）都进 `状态.特殊状态`。**

但 `特殊状态` 是 `Record<string, string>`，值只能是字符串。所以用**分层字符串**：

```
契约者.状态.特殊状态.保存 = "10层|每回合衰减15|生效:伤害+(10÷3)×10%"
契约者.状态.特殊状态.流血 = "持续3回合|每回合-4%最大HP"
骨卫兵.状态.特殊状态.约定之钉 = "2层|受震颤引爆时每层+1%最大HP"
```

| 段 | 给谁看 | 存什么 |
|---|---|---|
| 人类段 | 你 / 状态栏 | `10层` `持续3回合` —— 永远是字符串 |
| 引擎段 | 战斗引擎 | `衰减15` `护盾5%` `伤害+10%` —— 引擎能解析的修正 |
| 原文段（可选） | AI | `生效:…` —— 说不清的话兜底 |

**状态栏只读人类段，引擎只读引擎段，互不干扰。**

### 7.2 buff 的操作

引擎对 buff 只做三类操作：

1. **改层数**：`保存 +10`、`保存 -15`、`加护 +5` → 一律是层数增减
2. **读修正**：算伤害/护盾/反应时，把所有 buff 的引擎段加起来
3. **跑衰减**：回合末把每个 buff 的「持续」「衰减」递减一次

**例子：约定之锤的「保存」**

```
回合开始: 保存 +10 → "10层|每回合衰减15"
回合结束: 保存 -15 → "0层"（层数归零，buff 移除）
```

### 7.3 buff 与战斗解释的关系

**buff 是状态，战斗解释是规则。**

- 战斗解释说「命中时施加状态:冻结标记」→ 引擎往目标的 `特殊状态.冻结标记` 加一条
- 引擎算伤害时，读所有 buff 的引擎段，累加修正
- 战斗解释说「条件:冻结标记≥3」→ 引擎读目标的 `特殊状态.冻结标记`，解析层数，判定

**不需要在战斗解释里再造一个"冻结标记计数器"。** buff 就是计数器。

## 8. 距离与空间

### 8.1 一维距离条

**每个单位有个「距离」米数（相对玩家）**，移动距离属性决定每回合能拉近/拉开多少米。

```
玩家0m      骨卫兵 2m        骨弓手 14m
  ●───────────●──────────────●
```

**距离带**（查表）：

| 距离带 | 范围 | 命中修正 |
|---|---|---|
| 贴身 | 0–2米 | ±0 |
| 近距 | 3–10米 | ±0 |
| 中距 | 11–50米 | −1 |
| 远距 | 51–300米 | −2 |
| 超远距 | 301米以上 | −3 |

### 8.2 移动额度

**本回合额度 = 【移动距离】**（面板字段），每回合重置为满额，不累积。

**移动距离公式**（世界书 8.2）：

```
移动距离 = 5 + AGI修正值 + 移动距离额外加成
```

**AGI修正值 =（AGI实际值 − 5）× 位阶系数**（1/2/4/7/11，超脱 20）

**例子**：五阶角色 AGI=150
- AGI修正 = (150−5) × 11 = 1595
- 移动距离 = 5 + 1595 = 1600 米

这就是世界书里燕琉璃 `移动距离: 285米`、爱丽丝 `移动距离: 226米` 的来源。

### 8.3 射程硬门禁

**超出射程 = 无法发动，不是减命中。**

- 近战武器/徒手/近战技能：仅限 **贴身、近距**
- 投掷武器/手枪/短兵器：中距以内
- 步枪/弓弩/常规远程技能：远距以内
- 狙击枪/重炮/远程狙击类技能：超远距

**引擎在任何攻击进入伤害结算前，必须先确认射程合法。** 近战单位对远距目标出手 = 超程，必须先以移动贴近并扣减额度，否则该次攻击**直接无效**。

### 8.4 借机攻击

**脱离贴身/近距时触发**，消耗对方的【反应动作】（每回合仅 1 次）。

**免除只有四种**：
1. 脱离者用位移技能（写技能名）
2. 脱离者以次要行动做脱离准备
3. 对方本回合已用过反应动作
4. 对方被控/失能

**例子**：

```
你在 0m（贴身），骨卫兵也在 0m
你选「后撤 10 米」→ 触发骨卫兵的借机攻击
骨卫兵用反应动作「骨爪撕裂」→ 命中判定 → 你 171→155
你继续后撤到 10m
```

如果你用「弧光步」（位移技能），则免除借机攻击，直接到 10m。

### 8.5 脱离对抗

**想从贴身/近距脱离**：

```
脱离方 AGI修正 vs 追击方 AGI修正
```

- 成功 → 拉开一个距离带并脱离
- 失败 → 原地被咬住，仍吃借机攻击

追击方被控/失能则自动成功。

### 8.6 三种"换"（同一回合只能选其一）

| 换法 | 效果 | 代价 |
|---|---|---|
| 冲刺攻击 | 花掉 ≥一半额度并直接接敌，该次近战攻击 d20修正 +2 | 本回合放弃机会攻击 |
| 冲刺 | 把【主要行动】用于冲刺，获得额外一次等于【移动距离】的位移 | 此后不能再移动且不能再攻击 |
| 稳定射击 | 本回合未发生任何位移，远程攻击 d20修正 +1；以次要行动·瞄准则 +2 | 必须不动 |

### 8.7 掩体

在掩体且本回合未移动 → 闪避 +3，仅中距及以上生效（贴身无效）。必须写明具体物体。

### 8.8 狙击优势区间

处于【远距/超远距】且持狙击/重炮类武器时：
- 近战单位无法攻击到你
- 「瞄准」后下一次远程攻击 d20修正 +3，且不承受部位锁定的劣势

反之，狙击/重炮在【贴身/近距】攻击时 d20修正 −4。

## 9. 行动经济与回合循环

### 9.1 行动槽

**行动槽不是一个固定次数，是一个每回合重建的「预算对象」**：

```ts
type 行动预算 = { 主要: 1, 次要: 1, 移动: 1, 反应: 1, 免费: Infinity }
```

回合开始时重置为默认 → 依次叠加三层修正 → 每次用技能按它的 `行动类型` 扣 1（免费行动不扣）。

| 层 | 来源 | 例子 |
|---|---|---|
| 常驻 | 技能/装备/天赋/血统的「行动经济」词条 | 血统「双臂化」：每回合 +1 次要行动 |
| 本回合 | 状态/BUFF | 「加速」：本回合 +1 移动、+1 反应 |
| 消耗 | 玩家实际出招 | 用「裂骨重击」扣 1 主要 |

**行动经济修正在战斗解释的 `规则[]` 里**，通过 `数值修正(目标:反应动作)` 或 `数值修正(目标:次要行动)` 实现。

**例子：约定之锤的「保存神域」**

```jsonc
{
  "触发":"常驻",
  "作用域":"我方全体",
  "动作":[
    {"类":"数值修正","目标":"反应动作","量":{"源":"资源","名":"保存"}}
  ]
}
```

每回合开始时，引擎读所有单位的 `保存` 层数，累加到 `反应动作` 槽。

### 9.2 回合循环

**每回合 = 意图预公开 + 关键时刻暂停**

```
第 3 回合
────────────────────────────────────────
① 脚本调 1 次敌方 AI → 返回意图
② 面板显示敌方意图（还没掷骰）：
     骨卫兵 → 突进 + 骨爪撕裂(青空黎)   [可打断: 近战]
     骨弓手 → 齐射(青空黎)               [不可打断: 瞬发远程]
③ 玩家填自己的槽 —— 此时不需要等任何东西
     主要[裂骨重击] 次要[瞄准] 移动[后撤10米]
     反应[击溃 → 对 骨爪撕裂]   ← 有依据了
④ 点执行 → 引擎按先攻顺序一次跑完
────────────────────────────────────────
```

**结算时的暂停点**（待决点）：

1. **打断**（阶段 B1b）：被攻击方可消耗反应动作使用打断类（击溃/识破）
2. **防御**（阶段 B2）：被命中方可消耗反应动作使用防御类（招架/闪避/格挡/闪烁）
3. **转阶段**（阶段 D）：BOSS/隐藏BOSS 当前 HP 首次降至阶段阈值时
4. **濒死**（阶段 F）：HP 归零后每回合 CON 判定

**例子**：

```
① 骨卫兵 突进 2m→0m
   打断对抗：你 1d20=11+10=21  vs  它 1d20=17+12=29
   ✗ 打断失败 → 攻击照常 + 它本回合对你命中+2
   命中 1d20=16+14=30 ≥ 闪避24 ✔
   伤害 16 → 你 171→155
② 青空黎 后撤10m→ 裂骨重击 → 骨卫兵 96→75
③ 骨弓手 齐射(你)
   ⚠ 你没预置反应，命中 28 ≥ 24
   ┌─────────────────────┐
   │ 你将被击中，造成 13 点 │
   │ [招架][闪避][格挡][受着] │
   └─────────────────────┘
```

### 9.3 回合阶段

**每个完整回合依次执行阶段 A→B→D→F**（世界书原文）：

#### 阶段 A · 回合开始

- 资源恢复：耐力 +CON修正；MP +PER修正×0.5（向上取整）
- 生命状态检查：按当前生命百分比（健康/受伤/重伤/濒死）应用对应惩罚
- 结算所有「回合开始」触发的被动/buff/天赋/血统/状态

#### 阶段 B · 单位行动

按先攻顺序逐个单位执行：

- **阶段 B1 · 攻击检定**
  - 打断拦截（可选）
  - 规则系判定（可选）
  - 命中判定
  - 大失败（自然骰 1）

- **阶段 B2 · 防御**
  - 反应动作防御（招架/闪避/格挡/闪烁/护盾/比例类）
  - 防御结果

- **阶段 B3 · 伤害结算**
  - 基础伤害
  - 规则系判定（可选）
  - 乘区结算（部位锁定/暴击/效果乘区）
  - 最终伤害
  - 资源消耗

#### 阶段 D · 转阶段结算

BOSS/隐藏BOSS 当前 HP 首次降至阶段阈值时立即插入触发：

1. 清除 BOSS 全部负面状态，按血统/天赋面板回复 HP/MP
2. 获得面板标注的护盾或 1 回合无敌（防斩杀）
3. 解锁[职业]行职业技能与面板标注的阶段技能
4. **【必发必杀】** 立即强制施放[职业]行的必杀职业技能

#### 阶段 F · 回合结束

- 持续效果结算：中毒/流血/灼烧伤害、持续回合递减
- 状态判定：麻痹/冻结等导致的回合跳过或动作受限
- 尾结算：仅"回合结束"生效的被动
- 清理检查：移除到期 buff/debuff，更新剩余持续回合

## 10. AI 调用分工

### 10.1 三次调用

| 调用 | 时机 | 频率 | 模型建议 |
|---|---|---|---|
| **技能解释** | 战斗开始时 | 整场 1 次 | 快模型（3f） |
| **敌方意图** | 每回合开始时 | 每回合 1 次 | 快模型（3f） |
| **收尾正文** | 战斗结束时 | 整场 1 次 | 强模型（3.1p） |

**玩家每次出招不调 AI。** 引擎查缓存直接掷骰套公式。

### 10.2 技能解释

**输入**：所有参战单位的技能/装备/天赋/血统/称号（从 MVU 变量读出）

### 10.3 敌方意图

**输入**：
- 当前战斗状态（先攻/距离/HP/MP/耐力/状态）

- 玩家单位的技能/装备/天赋/血统（已翻译成战斗解释）

**任务**：为每个敌方单位决定本回合的行动意图（不掷骰）

## 15. 明确不做的事

### 15.1 不做二维战棋格子

**理由**：世界书里本来没这套规则，工作量比一维距离条大一个量级。

### 15.2 不做 NPC-NPC 距离

**理由**：世界书明确禁止「禁止计算或输出 NPC 与 NPC 之间的距离」，全场只以玩家为原点记录「距玩家多少米」。

### 15.3 不做跨副本的成长性效果

**例子**：「这件装备每击杀一个敌人永久 +1 攻击力」

**理由**：这类效果需要跨战斗记忆，超出了本脚本的范围。明确**不支持**，当叙事效果。

### 15.4 不做实时多人对战

**理由**：酒馆的架构是单机回合制，不支持实时多人。

### 15.5 不做战斗回放

**理由**：虽然状态机理论上支持回放，但 UI 工作量大，优先级低。未来可以加。

## 附录 B · 数值公式速查

### B.1 属性修正值

```
属性修正值 =（实际属性值 − 5）× 位阶系数
位阶系数：1/2/4/7/11（对应 1~5 阶，超脱 20）
```

### B.2 衍生属性

```
最大HP =（CON修正值+5）× HP系数 + HP额外加成
  HP系数：杂兵8 | 精英及精英（固有角色）10 | BOSS及BOSS（固有角色）20 | 隐藏BOSS及隐藏BOSS（固有角色）25 | 玩家系15

最大MP = PER修正值 × 10 + MP额外加成

最大耐力 =（CON修正值+5）× 10 + 耐力额外加成

防御 =（CON修正值+5）× 0.2（向下取整）+ Σ装备防御 + 防御额外加成

闪避值 = 10 + AGI修正值 × 0.5（向下取整）+ Σ装备闪避 + 闪避额外加成

移动距离 = 5 + AGI修正值 + 移动距离额外加成

负重上限 = STR实际值 × 5 + 负重额外加成
```

### B.3 判定

```
先攻 = 1d20 + AGI修正

武器命中 = 1d20 + 属性修正 + 被动加成 + AGI修正×0.2 ≥ 目标闪避值

技能命中 = 1d20 + 属性修正×(1 + 技能阶位/5) + 被动加成 + AGI修正×0.2 ≥ 目标闪避值或技能DC

近战物理=STR / 远程物理=AGI / 魔法=PER
```

### B.4 伤害六步

```
第一步_基础伤害：
  武器伤害（向上取整）= ((武器伤害骰 + 强化等级) × (1 + (阶位−1)/2) + 属性修正) × 武器倍率
  技能伤害（向上取整）= 技能基础伤害 × (1 + (阶位−1)/2)
  基础伤害 = 武器伤害 + 技能伤害
  实际防御 = CON×0.5（向下取整）+ 装备防御加成 + 防御额外加成
  混合伤害（最低1）= 基础伤害 − 实际防御

第二步_部位锁定：
  头部：DC+10×敌人位阶，伤害×1.5
  臂部：DC+5×敌人位阶，伤害×0.75
  腿部：DC+5×敌人位阶，伤害×0.75
  眼部/核心：DC+20×敌人位阶，伤害×2
  未声明部位：伤害×1

第三步_暴击：
  基础暴击率5%（自然20）；每10点AGI属性值扩大暴击范围1（最低扩展至自然15）
  暴击：×1.5；未暴击：×1

第四步_效果乘区：
  总增伤 = Σ(倍率−1)
  if 总增伤 ≤ 1.0：
    效果乘区 = 1 + 总增伤
  else：
    效果乘区 = 2 + (总增伤 − 1.0) × 0.25

第五步_防御方反应动作防御：
  打断类（击溃/识破）：打断检定 = 1d20 + 对应属性修正 × 3/4（向下取整），以劣势进行
  防御类（招架/闪避/格挡/闪烁）：减伤上限50%
  护盾：优先扣除护盾
  比例类：减伤/反伤 ≤50%

第六步_最终伤害：
  最终伤害 = (混合伤害 × 部位锁定倍率 × 暴击倍率 × 效果乘区) − 护盾值 − 减伤值
```

### B.5 规则系能力判定

```
判定值 = 1d20 + 关联属性修正 + 技能等额外修正

对抗目标 =（基础DC + 目标对应属性修正）× 类型系数 + 目标对应属性修正

基础DC：
  1阶 35 | 2阶 140 | 3阶 420 | 4阶 980 | 5阶 1925

类型系数：
  杂兵 0.6 | 精英 0.9 | BOSS 1.2 | 隐藏BOSS 1.5 | 契约者 1
```

### B.6 生命状态

```
健康 >70%：无惩罚
受伤 30~70%：剧烈动作劣势
重伤 1~30%：STR/AGI劣势、移动减半
濒死 0：每回合CON判定DC12，2次成功稳定/3次失败死亡
```
