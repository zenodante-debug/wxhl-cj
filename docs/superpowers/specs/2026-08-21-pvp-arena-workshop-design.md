# PvP竞技场（创意工坊）— 设计规格

> 日期: 2026-08-21 | 项目: wxhl-003 小手机新增「PvP竞技场」App

## 概述

在 wxhl-003 小手机中新增「PvP竞技场」桌面图标，实现"创意工坊"玩法：玩家把自己的契约者构筑（头部/属性/衍生属性/职业/通用技能/装备 六字段）提取成存档 JSON 下载发给作者；作者收录进世界书「契约者角色库」；其他玩家在竞技场浏览、选择这些契约者作为对手，发起对战——把对手写进 `stat_data.契约者.当前敌人.{对手名}` 并插入正文，交由角色卡现有对战系统驱动。

**核心决策**：
- 存储介质 = 世界书「契约者角色库」（条目 `enabled: false` 固定关闭，`getWorldbook()` 依旧能读到；不污染 AI 剧情上下文）
- 对手 = 写入 `当前敌人` 变量，**不**用 `importRawCharacter` 导入成酒馆角色卡
- 对战 = 沿用角色卡现有世界书对战系统，不新造战斗轮次
- 存档提取 = 直接 `getVariables()` 读取 + lodash 摘字段（不经过 AI），可选 AI 生成简介（默认开启、可关闭）
- 实现位置 = 挪进 wxhl-003，**不**新建独立项目 wxhl-cygf

## 数据模型

### 世界书「契约者角色库」

世界书名称默认 `契约者角色库`（常量 `WORKSHOP_WORLDBOOK_NAME`，可后续做设置项）。每个条目 = 一个契约者。

| 条目字段 | 内容 |
|------|------|
| `name` | 契约者名（显示名，=`契约者.头部.姓名`） |
| `content` | JSON 字符串（见下） |
| `enabled` | 恒为 `false`（作者手动固定关闭，不进 AI 上下文） |

`content` 内 JSON：

```json
{
  "契约者": {
    "头部": { ... },
    "属性": { ... },
    "衍生属性": { ... },
    "职业": { ... },
    "通用技能": { ... },
    "装备": { ... }
  },
  "简介": "一句话卖点",
  "上传者": "提供存档的玩家名"
}
```

### 存档字段范围（精确对齐角色卡 schema）

只含六字段，**排除**以下全部：`背包`、`经济`、`个人产业`、`副本经历`、`人际关系`、`小队`、`当前副本元数据`、`固有角色`、`当前副本任务`、`状态`、`资格分`、`赛季信息`、`排行榜`。

### 校验 schema（`PvPSaveSchema`）

用 zod 定义 `PvPSave`（契约者六字段 + 简介 + 上传者），解析时按角色卡 schema 的 transform 重算派生值（如 `属性.实际` = 基础 + 加成 + 自定义加成）。坏条目跳过并 toastr 提示。

### 阶位分组

```text
1阶 / 2阶 / 3阶 / 4阶 / 5阶 / 超脱
```
`契约者.头部.阶位` 字符串直接匹配分组；未知阶位归入"其他"或置于末尾。列表按分组顺序展示，组内按等级从高到低。

## 数据流

### 玩家侧「上传角色构筑」（`extractMySave`）

1. `getVariables()` 读取 `stat_data.契约者`（复用 wxhl-003 `readPlayerData` 探测模式：message → -1 → chat 逐级找）
2. `_.pick(契约者, ['头部','属性','衍生属性','职业','通用技能','装备'])` 摘六字段
3. 若开关开启：`generateRaw` 按构筑生成一句话简介（复用 `aiGenerate`/`extractJSON` 模式）
4. 组装 `{契约者: 六字段, 简介, 上传者}` → Blob 触发下载 `.json` 文件
5. 玩家把文件发给作者

### 作者侧「收录契约者」（`writeToWorldbook`）

1. 粘贴存档 JSON / 选择文件 → `PvPSaveSchema.parse()` 校验预览
2. 确认 → `createWorldbookEntries(WORKSHOP_WORLDBOOK_NAME, [{ name, enabled: false, content: JSON.stringify(save) }])`
3. 「移除条目」→ `deleteWorldbookEntries`

### 玩家侧「发起对战」（`startBattle`）

1. 解析目标条目 `content` → 六字段契约者对象
2. 写变量：`Mvu.replaceMvuData()` 在当前楼层变量中写入 `stat_data.契约者.当前敌人.${对手名}` ← 契约者对象（`当前敌人` 结构 `{外貌,头部,属性,衍生属性,职业,通用技能,装备,状态,背包}`，六字段直接对齐，缺的用 prefault）
3. 写正文：`createChatMessages([{role:'assistant', message: 对手登场描述}])`
4. 竞技场收起，交给卡内现有对战系统

**写入策略**：不清空、不覆盖现有 `当前敌人`，仅插入 `当前敌人.{对手名}`。（设计前提：进入竞技场时玩家通常无敌人；即使有，也仅插入不冲突。）

## 错误处理

| 状态 | 处理 |
|------|------|
| 世界书不存在/无契约者 | 空态引导文案 +「如何收录」说明 |
| 条目 JSON 损坏 | zod 校验失败 → 跳过该条目，toastr 提示 N 条损坏 |
| 发起对战未检测到玩家变量 | 提示"未检测到玩家契约者数据"，终止 |
| 收录时 JSON 非法 | 校验预览阶段报错，不写入 |
| AI 简介失败 | 降级为无简介（不阻塞下载） |
| 对战中（已有同名校验） | 直接插入 `当前敌人.{对手名}`，不清空不覆盖 |

## UI 状态覆盖

| 状态 | 展示 |
|------|------|
| 空列表 | 居中提示 +「如何收录」说明 |
| 提取构筑中 | loading + "正在提取构筑..." |
| AI 简介生成中 | 开关旁 loading + "AI 生成简介..." |
| 收录校验预览 | 契约者名/等级/阶位/职业 只读预览 + 确认按钮 |
| 对战确认 | 弹窗显示对手名 + 提示"将写入敌人数据并开始对战" |

## 复用

- **API 调用**: 复用 wxhl-003 `aiGenerate()` / `extractJSON()` 模式
- **世界书**: 复用 `getWorldbook()` / `createWorldbookEntries()` / `deleteWorldbookEntries()`；`getWorldbookContent()` 用于 AI 简介
- **变量读取**: 复用 `readPlayerData` 的探测模式（message → -1 → chat）
- **样式**: 复用 `.app-page` / `.app-header` / `.scroll-area` / `.dialog-mask` / `.dialog-box` 等
- **localStorage**: 无关（数据全在世界书）
