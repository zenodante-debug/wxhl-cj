# 一个卡面条目 → 多招可用 + 规则系程度 — 实施计划

日期：2026-10-09
范围：`src/wxhl-combat/`（翻译粒度 + 引擎小缺口 + UI 分组）
来源：玩家给的实例（自然系·闪闪果实），以及两条裁决：

> 「还有一些复杂的情况，这个技能，两个效果（一个效果和一个极意），但是效果内部又分为好几个效果，
> 模型会怎么拆？玩家想要释放具体的效果该怎么用」
> 「穿透、免疫、都是规则系（补充知识）」

## 0. 问题：一个卡面条目里塞着好几招

玩家实例（节选）：

| 卡面里的东西 | 它其实是什么 | 现在一条解释塞得下吗 |
| :--- | :--- | :--- |
| 光子化身·常驻免疫常规物理打击 | 规则系**免疫**（限类型） | 塞得下，但"限类型"表达不了 |
| 光折射（移动 +40 米、无视障碍与借机） | 移动距离修正 + 词条 | ✅ |
| 光子镭射（主动轰击，无视 50% 防御与抗性） | 主要行动 + **规则系穿透（程度 50%）** + 多属性伤害 | ❌ 多属性 / 程度表达不了 |
| 【八咫镜·光行】(次要**或**反应，**每场限 2 次**) | 独立一招 | ❌ 多行动类型 / 次数限制表达不了 |
| 【八尺琼勾玉·净世天光】(主要行动、耗**最大MP 8%**、冷却 3) | 独立一招 | ❌ 按比例消耗表达不了 |

**根因**：我们的输出契约是「一个卡面条目 → **一条**战斗解释」（编号回填、一条一套行动类型/消耗/冷却）。
于是模型只能二选一：把三招的规则糊在一条里（玩家**没法单独放其中一招**，冷却与消耗也对不上），或者整体放弃给空壳。

## 1. 设计

### 1.1 一个条目 → N 条子技能（翻译粒度）

- **输出**：允许同一个 `编号` 出现**多条**解释；每条是一个独立可用的招。
  命名约定：卡面里**已经给了名字**的（【八咫镜·光行】）直接用那个名字；
  没给名字的主动招用「母技能名·说明」（如 `光子化身·光子镭射`）；常驻部分归到一条被动（如 `光子化身·常驻`）。
- **每条带 `母条目`**（母技能名）—— 只用于界面分组显示"这几招是从同一个卡面来的"，不参与判定。
- **管道**：`解析批量翻译结果` 按编号分组；组内**任何一条不合法 → 该编号整体判失败**（可重翻），
  避免"拆了三条只落一条"的静默丢失。
- **缓存**：指纹 → **解释列表**（老缓存是单条 → 读时包成数组，向后兼容）。
- **界面**：行动下拉天然按行动类型过滤 → 三招各自出现在该在的位置；详情面板把同一个 `母条目` 的招分组显示。

### 1.2 规则系带程度（按玩家补充：穿透/免疫都是规则系）

世界书的规则系判定（判定值 = 1d20 + 关联属性修正；对抗目标 =（基础DC + 目标修正）×类型系数 + 目标修正）
**保持原样**；只给规则系效果的声明加一个**程度/限定**：

- `{"类":"规则系判定","效果":"穿透","程度":0.5,"目标":"攻击目标"}` → 过了判定后，**无视目标 50% 防御与全元素抗性**
  （程度省略或 = 1 → 全穿，即现在的行为）
- `{"类":"规则系判定","效果":"免疫","限定":"常规物理","目标":"自身"}` → 命中的攻击属于该限定 → 免伤
  （限定省略 → 全免，即现在的"无敌"；判定与对抗照旧由防火墙负责）
- 其余认不得的效果名**照旧**：判定照掷、过了交给叙事（开放集合，已实装）。

### 1.3 三个小缺口

| 缺口 | 设计 |
| :--- | :--- |
| **每场限次**（每场限 2 次） | `战斗解释.每场限次?: number`；`战斗单位.已用次数: Record<string, number>`（随战斗快照持久化）；结算门禁：已用 ≥ 限次 → 跳过并说明；用掉后 +1 |
| **按最大值的比例消耗**（最大MP的 8%） | `解析消耗` 支持 `最大MP的8%` / `最大MP 8%` / `MP上限的8%`；扣 `ceil(最大值 × 比例)` |
| **多属性加权伤害**（PER×3.6 + AGI×3.2） | `战斗解释.属性加权?: {属性, 系数}[]`；技能伤害 = Σ(对应属性修正 × 系数) × 技能阶位成长；`关联属性/伤害倍率` 作为缺省（不写加权时行为完全不变） |
| **一条技能多行动类型**（次要/反应） | `行动消耗` 允许**数组**；`列行动选项` 让它在每个匹配的下拉里都出现；用掉时扣**所选**那个槽 |

## 2. 实施步骤（每步 TDD，先写失败测试）

1. **规则系程度**：`程度` / `限定` 字段 + 伤害管线按程度折算防御与抗性 + 免疫按限定判定（物理/魔法按攻击的属性键区分）。
2. **每场限次**：字段 + 计数 + 门禁 + 持久化 + 日志（"本场已用尽"）。
3. **比例消耗**：`解析消耗` 支持比例 + 结算按最大值扣 + 提示词口径补 `最大MP的X%`。
4. **多属性加权**：字段 + 技能伤害按加权算 + 提示词配方（"造成 (PER修正×3.6 + AGI修正×3.2) 伤害"怎么写）。
5. **多行动类型**：`行动消耗` 支持数组 + 列行动选项 + 本地校验/提示词。
6. **翻译一格多招**：输出多条 + 命名约定 + `母条目` + 解析按编号分组（组内一条坏 = 整组失败）+ 缓存多值 + 向后兼容。
7. **界面分组**：详情面板按 `母条目` 分组显示子技能（行动下拉不动 —— 已按行动类型过滤）。
8. **提示词总纲**：新增「一个条目里塞了好几招怎么拆」段落 + 用玩家这张闪闪果实当范例。
9. **回归**：`npx vitest run` / `tsc`（基线 44）/ `npm run build` / `bash scripts/push-combat.sh`。

## 3. 验收

以玩家这张卡为例，翻译后应得到**四条独立可用**的招：
`光子化身·常驻`（被动）/ `光子化身·光子镭射`（主要行动，多属性伤害 + 穿透50%）/
`八咫镜·光行`（次要行动 或 反应动作，每场 2 次）/ `八尺琼勾玉·净世天光`（主要行动，耗最大MP 8%、冷却 3）。
每条都能在对应下拉里单独选中；冷却/消耗/次数各自独立；详情面板能看出它们同源。

## 5. 追加需求（2026-10-09 第三次；玩家原话四条）

> 「应该每个行动都增加可选目标吧，现在是所有行动都是一个目标，而且，现在的免费行动无法选择目标。」
> 「另外，现在 aoe 技能无法实现！」
> 「还有环境、场地 buff 这种，目前也没有实现。」
> 「还有能力与能力之间的连携，比如，一个技能是取消一个可选技能的冷却，这种也目前实现不了」

### 5.1 每个行动**各自**选目标（含免费行动）

**现状**：界面上每个单位只有**一个**目标下拉（`目标表[键]`），主要/次要/免费共用；
免费行动是一组复选框（`免费: string[]`），**根本没有目标** —— 想"次要给自己上 buff、主要打敌人"做不到。

**设计**：
- 数据：`行动槽填写` 的每个槽各自带目标；`行动顺序` 的条目从 `string` 改成 `{键, 值, 目标}`（顺序与目标天然绑在一起）。
  兼容：老形状（单一目标）仍可解析 → 作为所有行动的缺省目标。
- 引擎：**不用改** —— `意图行动` 本来就每条自带 `目标`，`构造行动声明` 把各自的目标填进去即可。
- UI：主要/次要下拉**各配一个目标选择**；免费行动从"复选框"改成"添加一条"（每条自带目标 + 在行动顺序里可 ↑↓）；目标下拉把"敌方（攻击）/我方（支援）"分组照旧。

### 5.2 AoE 技能真正能用

**现状**：`范围伤害` 动作存在，但
1. **中心 = 施法者自己的距离**（打不了远处那片敌人）；
2. 只做"固定量扣血" —— **不走六步**（无命中判定、不吃防御/减伤/暴击），与"大范围混合魔法穿透伤害"这种卡面语义对不上。

**设计**：
- 中心改为**所选目标的位置**（选中 AoE 后，目标下拉的语义变成"选定中心"，文案改为「中心」）；
  没有选目标时退回"以自身为中心"。
- 半径内的每个敌对目标**各走一遍单目标伤害管线**（命中判定 + 六步 + 状态），并**排除施法者**（已有）。
- 提示词配方升级：`{"类":"范围伤害","中心":"攻击目标","半径":80,"量":{…}}` 明确"以所选目标为中心、半径内所有敌方各吃一遍这套伤害"；
  需要掷命中时同样对待（现状：AoE 不掷命中 → 设计里给出选择，见 §6 待确认）。

### 5.3 环境 / 场地 buff（领域）

**现状**：`{"类":"领域",…}` 在类型里声明了、`落效果` 里**只写一条日志就丢**（`状态.领域` 永远是空数组）——
所以"森罗古界：敌方治疗降低 70%、受伤分裂毒花"这类场地效果**完全没有落地**。

**设计**：
- `落效果` 把领域落进 `状态.领域`：`{名, 中心距离, 半径, 持续, 内部规则[]}`（按名去重，同名后覆盖先）。
- **每回合开始**（阶段A）跑一遍：对**每个在半径内**的单位执行领域内的规则（作用域照旧：`敌方全体`/`我方全体`/`自身`）；
  单位**走进走出**自然受影响（按距离实时判定），不是"施法时圈定名单"。
- 持续到期（阶段F 递减）→ 移除并留一条日志；面板上加一块「场地」显示当前领域与剩余回合。
- 提示词配方：领域怎么写（内部规则照常用 常驻/回合开始 等触发点 + 作用域）。

### 5.4 能力连携（**通用**，冷却只是一个例子）

玩家补充：「冷却连携只是一个例子，还可能有伤害连携、什么乱七八糟的联动」——
所以要做的不是"一个清冷却的动作"，而是**技能级作用的动作族** + **玩家选技能**：

**（a）玩家选技能（`需选择技能: true`）**
- `战斗解释.需选择技能?: true` → 界面上选中该技能时多一个「选择目标技能」下拉
  （列出该单位**能选**的技能：默认列全部、可按 `候选筛选` 收窄，例如只列"在冷却中的"）。
- 选中结果随行动一起传进引擎（`意图行动.选择技能`），规则求值上下文里可读（`选中技能`）。

**（b）技能级作用的动作族 `{"类":"技能作用", "操作": …, "名": "选中技能" | "具体技能名" | "全部", …}`**

| 操作 | 干什么 | 玩家例子 |
| :--- | :--- | :--- |
| `清冷却` | 清除该技能的剩余冷却 | 「取消一个技能的冷却」（你举的例子） |
| `减冷却` | 减少 N 回合冷却（量） | 「冷却缩短 2 回合」 |
| `重置次数` | 重置"每场限次"的已用计数 | 「再获得 2 次八咫镜」 |
| `加次数` | 每场限次 +N（量） | 「额外使用一次」 |
| `挂词条` / `移除词条` | 给该技能挂/摘标签，供条件判断 | 「该技能下一次释放×2 伤害」 |
| `技能加成` | 给该技能下一次释放加数值修正（目标 + 量，用完即清） | 「使下一个伤害技能伤害 +50%」 |

- 条件里也能读技能词条：`{"源":"技能词条","名":"强化"}` —— 于是"如果某技能被强化过就…"这类联动也能写。
- 认不得的 `操作` → 记日志跳过（不静默）。
