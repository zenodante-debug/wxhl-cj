## 1. 战甲着装（变身 / 二阶段 / 形态变化）

**设计**：装备/技能卡面写了「展开后…」「变身」「变形」「阶段变化」这类**涉及属性和衍生属性向上增长**的效果 → 翻译器拆出一个**主动技能**（`类型: 主动`，`行动消耗: 主要行动`），规则里写 `{"类":"切换形态","到":"展开状态"}`。

**落点**：
- 提示词补「装备/技能卡面写了『展开后…』/『变身』/『变形』/『阶段变化』这类**涉及属性和衍生属性向上增长**的效果 → 拆出一个切换形态的主动技能」；
- `效果预览` 把 `切换形态` 翻成人话（"切换到形态「展开状态」"）；
- 引擎侧 `切换形态` 已经存在（落成「形态：X」状态），不用改。

**验收**：零号超巨星机甲翻出来 → 一条「主炮直击」（主要行动）+ 一条「战甲着装」（切换形态到「展开状态」）。

## 2. 技能伤害含武器骰 + 释放来源（选武器/徒手）

**设计**：`结算技能` 里 `基础伤害 = 武器 + 技能`，但 `武器` 用的是**主武器**的骰值 —— 卡面里写了「伤害骰」的装备，它的骰值根本没进伤害。

**修法**：
- `结算技能` 里读 `解释.伤害骰`（卡面里写了就优先用它，否则退回主武器）；
- **释放来源**：`行动声明` 加一个 `武器来源?: '主武器' | '副武器' | '徒手'`，界面上技能释放时让玩家选（默认主武器）；没选就用主武器（老行为）。

**落点**：`loop.ts:1740` 附近（`手持武器` 的选择逻辑）+ `types.ts`（`行动声明.武器来源`）+ `BattleView.vue`（技能释放时多一个下拉）。

**验收**：零号超巨星机甲的「主炮直击」打出的伤害里，`武器` 那部分用的是 20d40（注入伤害骰 6 → 20×6=120 骰值总和），不是主武器的骰。

## 3. 锁血整改

**设计**：plan 已写好（`2026-10-10-wxhl-combat-lock-hp-floor.md`）——「锁血下限」只在**当前回合**生效：一次攻击把 HP 打到低于 N% 时，**这一回合**锁在 N%；**下一回合**重新计算。

**落点**：`loop.ts:1844-1864` 的 `锁血下限` 分支，加一个"本回合是否已锁过"的标记（记在单位上，回合开始时清掉）。

**验收**：带「锁血下限 0.15」的单位，HP 掉到 15% 之后，**下一回合**受击 → 该死的时候死（不是又拉回 15%）；同一回合内，一次攻击打穿到 15% 以下 → 锁在 15%（这一回合不死）。

## 4. 快捷物品栏（背包补给品）

**设计**：
- 开战前，给玩家的角色和队友提供**三个可选栏位**，叫做「快捷物品栏」；
- 点击栏位 → 选项框，可以选择**三件背包的物品**（直接读变量拉取背包的物品）；
- 这三件物品**加入进战斗解释翻译**里（和技能/装备/天赋/血统一起翻）；
- 使用这三件物品是**免费行动**（不限次数，数量忠诚地读取背包里这个物品变量的数量）。

**落点**：
- `store.ts` 读背包变量（参照 wxhl-003 小手机：工坊/自由市场/状态栏怎么读，照同一套）；
- `SetupView.vue` 加三个下拉（选背包里的物品）；
- `CombatView.vue` 开战时把选中的三件物品并进 `效果源`（一起翻）；
- 引擎侧：快捷物品 = 免费行动（`行动消耗: 免费行动`），数量读背包变量。

**验收**：开战前给契约者选了「绷带 × 99」「恢复药水 × 99」「MP 恢复药剂 × 99」→ 战斗中这三个是免费行动，数量从背包读。

## 5. 从持久化恢复战斗 → 敌人意图没了

**设计**：`onMounted` 里恢复了状态/意图模式/日志，但**没恢复 `敌方意图列表`** —— 重开面板后 `敌方意图列表.value = []`，下一回合直接空过。

**修法**：`构建战斗状态快照` 里把 `敌方意图列表` 也存进去；`恢复战斗状态` 里读回来；`onMounted` 里 `敌方意图列表.value = 恢复.敌方意图列表 ?? []`。

**落点**：`engine/persist.ts`（快照多一个字段）+ `CombatView.vue`（`onMounted` 里恢复）。

**验收**：重开面板 → 敌人意图还在（不是空过）；"已从持久化恢复战斗"只刷一遍（不是三遍）。

## 6. 伤害倍率全写 0

**设计**：`单位效果源` 接口里**没有 `伤害倍率` 这个字段** —— 模型只能从「效果」文本里猜，猜不到就填 0。不是"读不出来"，是**源头就没给它**。

**修法**：`单位效果源` 加一个 `伤害倍率?: number` 字段；`技能条目转效果源` 里从卡面读出来（`s?.伤害倍率`）；提示词里"伤害倍率"那一条改成"卡面写了就照填"。

**落点**：`store.ts`（接口 + 转换函数）+ `skillInterpreter.ts`（提示词）。

**验收**：卡面写了「伤害倍率 2.5」的技能 → 翻译结果里 `伤害倍率: 2.5`（不是 0）。

## 7. "必定暴击"读不出来

**设计**：引擎里**没有"必定暴击→必暴"的归一化** —— `收集规则系` 里读的是原样字符串（`必定暴击` ≠ `必暴`），防火墙里 `引擎认得的规则系效果` 只认 `必暴`。

**修法**：`收集规则系` 里加归一化（`必定暴击` / `必定命中` / `必定即死` → `必暴` / `必中` / `即死`）；提示词里补"必定暴击 → 必暴"（模型照写）。

**落点**：`loop.ts`（`收集规则系` 里归一化）+ `skillInterpreter.ts`（提示词）。

**验收**：卡面写了「必定暴击」的技能 → 翻译结果里 `效果: '必暴'`（不是 `必定暴击`）。

## 8. 乘区读不到（常驻被动被翻成主动）

**设计**：常驻被动（`类型: 被动` + `行动消耗: 无`）该落成状态写进 `常驻修正`，但翻译器把它们翻成了**主动技能** —— 于是乘区加成**完全没生效**。

**修法**：提示词里补"常驻被动（狂热裁决者 / 痛楚转化 / 舍生取义…）→ `类型: 被动` + `行动消耗: 无`"；校验器里**主动但无伤害的被动**（`伤害倍率: 0` + 规则里全是常驻修正）→ 自动归成被动（不判失败）。

**落点**：`skillInterpreter.ts`（提示词 + 校验器）。

**验收**：狂热裁决者（常驻被动）→ 翻成 `类型: 被动` + `行动消耗: 无`，开战时落成状态写进 `常驻修正`（乘区加成真的生效）。

## 9. 刷新要重填 API

**设计**：设置存在 `getVariables({type:'script', script_id})` 里（脚本变量）—— **刷新酒馆页面不会丢**，但脚本变量是**跟着脚本走的**，换角色卡/换聊天文件就没了。这是设计，不是 bug。

**修法**：**不改** —— 这是设计。但如果玩家想要"刷新后还在"，得把设置存到**聊天变量**（`type: 'chat'`）里（跟着聊天文件走，换卡不换聊天就还在）。

**落点**：`settingsStore.ts`（`读设置` 改成先读聊天变量、没有再读脚本变量；`保存` 两边都写）。

**验收**：刷新页面 → 设置还在（读聊天变量）；换角色卡 → 设置还在（聊天变量跟着聊天走）。

## 10. 战斗中的 AI 调用不能后台

**设计**：`开始战斗` / `开始回合` 里的 `await` 会**卡住界面**（玩家退出悬浮窗就断了）—— 该改成 fire-and-forget（不挡卸载）。

**修法**：`开始战斗` / `开始回合` 里的 `await` 改成 `void`（不挡卸载）；`写战斗状态` 也是 fire-and-forget。

**落点**：`CombatView.vue`（`开始战斗` / `开始回合` 里的 `await` 改 `void`）。

**验收**：点开战 → 界面不卡（后台跑）；退出悬浮窗 → 战斗照常跑（不中断）。

## 12. 「必定」拆分（必定 + 暴击/命中/斩杀…）

**设计**：「必定」是**规则系前缀**（必中/必暴/即死/锁定/斩杀…），不是一个单独的效果 —— 模型写「必定暴击」「必定斩杀」「必定锁定」时，引擎要**拆开**（`必定` + `暴击`），再归一到引擎认得的效果名（`必暴` / `必中` / `即死` / `锁定` / `斩杀`）。

**修法**：`收集规则系` 里加归一化（`必定暴击` → `必暴`、`必定命中` → `必中`、`必定斩杀` → `即死`、`必定锁定` → `锁定`…）；提示词里补"必定 + X → 规则系判定，效果写 X（不写『必定』）"。

**落点**：`loop.ts`（`收集规则系` 里归一化）+ `skillInterpreter.ts`（提示词）。

**验收**：卡面写了「必定暴击」的技能 → 翻译结果里 `效果: '必暴'`（不是 `必定暴击`）；卡面写了「必定斩杀」的技能 → `效果: '即死'`（不是 `必定斩杀`）。

## 13. 部位选择（第二步_部位锁定）

**设计**：部位是**攻击的一部分**（玩家选这次攻击打哪），不是技能写死的 —— 现在 `部位` 是 `战斗解释` 里的字段（模型写死），界面上**没得选**。

**修法**：`行动声明` 加一个 `部位?: 攻击部位`；界面上技能释放时让玩家选（默认不选 = 无部位加成）；引擎侧 `部位` 从 `行动声明` 读（不是从 `战斗解释` 读）。

**落点**：`types.ts`（`行动声明.部位`）+ `BattleView.vue`（技能释放时多一个下拉）+ `loop.ts`（`技能参数` 里读 `行动.部位`）。

**验收**：技能释放时选「头部」→ 这次攻击的部位是头部（伤害 ×1.5，DC +10×敌人位阶）；不选 → 无部位加成（老行为）。

## 14. 移动是加减法，不是坐标替换

**设计**：移动输入框输入的是**位移量**（「+10」→ 加 10），不是**目标坐标**（「移动到 10」→ 到 10）—— 现在 `结算移动` 里 `目标距离 = 行动.距离`，是**坐标替换**。

**修法**：`结算移动` 里 `目标距离 = 当前.距离 + 行动.距离`（位移量）；输入框的 placeholder 改成「+10 = 向前 10 米」。

**落点**：`loop.ts`（`结算移动` 里 `目标距离` 改成 `当前.距离 + 行动.距离`）+ `BattleView.vue`（placeholder 改）。

**验收**：我在「9」输入「+10」→ 移动到 19（不是 10）；输入「-5」→ 移动到 4（不是 -5）。

## 15. 刷新要重填 API

**设计**：设置存在 `getVariables({type:'script', script_id})` 里（脚本变量）—— **刷新酒馆页面不会丢**，但脚本变量是**跟着脚本走的**，换角色卡/换聊天文件就没了。这是设计，不是 bug。

**修法**：`读设置` 改成先读**聊天变量**（`type: 'chat'`）、没有再读脚本变量；`保存` 两边都写（聊天变量 + 脚本变量）。

**落点**：`settingsStore.ts`（`读设置` 改成先读聊天变量；`保存` 两边都写）。

**验收**：刷新页面 → 设置还在（读聊天变量）；换角色卡 → 设置还在（聊天变量跟着聊天走）。

### 19.1 ~~翻成主动技能~~ —— **证伪**

```ts
for (const 规则 of 有效规则(解释)) {
  if (规则.触发 !== '常驻' && 规则.触发 !== '进入战斗') continue;
```

**没有一处读 `解释.类型`**（全文件 grep：`类型` 只出现在 `u.类型`＝单位类型、`行动.类型`＝行动槽）。

### 19.2 真实根因（4 条，按"读不到"的程度排序）

**R1 · `职业特性` 从来没进过待翻译清单**【最彻底的一条，100% 读不到】

- 权威 schema：`职业Schema.职业特性 = z.record(特性名, z.object({ 效果: z.string() }))`
  —— 是 `职业技能` / `传承技能` 的**兄弟字段**。
- `store.ts:251`：`const 技能来源 = [实体.通用技能, 实体.职业?.职业技能, 实体.职业?.传承技能];`
  —— **三个都在，独独漏了 `职业.职业特性`**。
- 后果：加百列卡里的 `职业特性_主职业`（天使之躯/狂热裁决者/光明亲和/破除万法/信仰锚点）
  与 `职业特性_副职业`（异端克星/审判威压/铁血意志）—— **模型根本没看见过**。
  这正是玩家原话「职业特性……都读不到」的字面意思。

**R2 · `托管` 引擎根本不执行 = 安静的空壳**【量最大的一条】

- 实测：全仓库 grep `托管`，**引擎侧零消费者**（只有 `effectPreview` 显示、`types` 定义、`skillInterpreter` 产出）。
  进了托管的条目在战斗里**什么都不做**。
- 玩家上一次的 44 项可疑清单里，几乎每条都是「拆解 N 条 → 映射 0~1 条规则 + N 条托管」——
  也就是**这些效果一条都没生效**。
- 而 2026-10-10 我做了两处放宽，把它们从"响亮的失败"改成了"可以接受的结果"：
  1. `skillInterpreter.ts:516-522`：拆解有内容、规则 0 条 → **静默转成托管**，不判失败；
  2. `effectPreview.ts:255` + `CombatView.vue:571-578`：判据改成
     `拆解数 > 规则数 + 托管数`，于是 **托管被明确写成"不算可疑"**。
- 这**直接违反** memory `wxhl-loud-failure-over-silent-shell`（放宽校验导致技能静默失效的改动一律回退）。
  玩家当时问「n 条效果 n 条托管是不是正常的？」——**不正常**，那是 n 条效果全部失效。

**R3 · 「翻倍 / ×N」这类乘法效果根本没有可表达的写法**

- `数值修正` 的所有 目标 **只有加法**。卡面「基础伤害骰强制翻倍」（巨剑精通）无法表达。
- 模型自己发明了 `量: {源:'表达式', 式:'基础伤害骰'}`（"加上它自己" = 翻倍）。
- 而表达式求值器（`combatInterpreter.ts:237`）的标识符表里**没有** `基础伤害骰` / `攻击倍率` /
  `伤害乘区` / `武器倍率` 这些名字 → **抛错** → `开战规则结算` 捕获后**整条规则丢弃**。
- 实测战报：`忽略：「契约者」的常驻规则「巨剑精通」求值失败：表达式里的未知标识符: 基础伤害骰`
  —— 玩家在战报角落里才看得到，效果已经没了。

**R4 · `规则系判定` 缺「目标」→ 动作被剪 → 顺带把同一条规则里的数值修正一起赔进去**

- `动作结构完好`（2026-10-10 新加）要求 `规则系判定` 必须有 `目标`，否则该动作被剪。

### 19.6 这一批新踩的坑（补进 §18.4 的同类）

8. **提示词里不能出现反引号** —— §18.4 第 4 条又踩了一次（写 `量` 时手滑），
   模板字符串当场截断、整个文件编译不过。**写提示词时一律用「」。**
9. **用户可见的字符串里不能混 Markdown 记号** —— `effectPreview` / 复核清单的文案是
   **纯文本**渲染的，写 `**托管不会生效**` 玩家看到的就是两个星号。

## 20. 特殊资源「能识别但用不了 / 从来没写入」（2026-08-11 玩家实测）

玩家口径：
> 「特殊资源好像是虽然可以识别，但是无法使用。正常来说，特殊资源是写在特殊状态栏里的，
>   表现在战斗里，角色详情的状态与增益里，但是之前都没有写入。
>   比如魔网法师的【环位】、或者什么狂战士的【愤怒】资源，每受伤一次获得一个【愤怒】，
>   5层【愤怒】则使伤害×2，10层【愤怒】则每回合可以多行动一次……」

### 20.1 根因（读代码 + 权威 schema 查证）

引擎里**有**自定义资源这个通道：`战斗单位.资源: Record<string, number>`
（types.ts:45 注释就写着"任意命名资源（保存/充能/加护/冻结标记…）"），
模型写 `{"类":"资源","名":"愤怒","操作":"获得","量":{...}}` 引擎也**真的会加**（loop.ts:2362-2389）。
所以"能识别"是真的。问题在**它到不了任何一个玩家看得见的地方**：

| # | 事实 | 证据 |
| :--- | :--- | :--- |
| **R1** | **战斗界面完全不显示 `资源`** —— 单位卡与详情面板的「状态与增益」都只遍历 `单位.状态` | `BattleView.vue:108`（单位卡）、`:124-130`（详情面板）都只读 `u.状态`；全仓库 grep `资源` 在 views 里 0 命中 |
| **R2** | **`写回战斗结果` 从不写 `资源`** —— 只写 `衍生属性.*_当前` 与 `状态.特殊状态` | `store.ts:894-913`。所以卡面的「特殊状态栏」里永远没有它 |
| **R3** | `字符串转buff`（特殊状态 → 状态）**是死代码**，全仓库只有定义没有调用 | grep `字符串转buff` 仅 `buffMapper.ts:42`。即：特殊状态是**只写不读**的单向通道（下一次开战不会读回） |
| **R4** | 提示词里自定义资源只有**一句话**，没有"每受伤+X层 / 攒够N层解锁"这类真实卡面的配方 | `skillInterpreter.ts` 的「资源消耗」段只讲 MP/耐力 |

另外确认过：**权威 schema 里没有 `资源` 字段**（`状态Schema` 只有 `生命状态` + `特殊状态: Record<名, 描述字符串>`）。
所以`资源`**只能**住在「特殊状态」里 —— 和玩家的说法一致。

### 20.2 修法

| # | 修 | 落点 |
| :--- | :--- | :--- |
| F1 | 单位卡 + 详情面板「状态与增益」区**显示自定义资源**（`愤怒 ×3`）。值同样出现在单位卡上（和"状态:"那行并排） | `BattleView.vue` |
| F2 | `写回战斗结果` 把 `单位.资源` 也写进 `状态.特殊状态`，编码用 buffMapper 认得的 `N层`（纯数字、人类可读，且 `字符串转buff` 将来接上能原样读回） | `store.ts` |
| F3 | 提示词补【特殊资源怎么写】：获得/消耗/按层数触发阈值（就用玩家给的【愤怒】例子） | `skillInterpreter.ts` |

### 20.3 明确**不做**的（说清楚，免得以为是漏了）

- **不做跨战斗持久化**：战斗结束把资源写进卡面后就归零，下一场从 0 重新算。
  理由：`字符串转buff` 这条读回路现在是死的，接上它是一个独立的话题（涉及"哪些状态该跨战斗保留"，
  需要玩家定夺）。而且环位/愤怒这类资源按世界书本来也是每场重算。
- **不做"5层→伤害×2"的自动推导**：那是**模型的活**（写条件规则），引擎只提供
  `{源:'资源',名:'愤怒'}` 取值与 `条件` 判定 —— F3 把配方教给它。

### 21.1 玩家已裁定的三件事（2026-10-11 确认，别再猜）

1. **用量**：用一次扣一个，**战斗中记账、收尾时写回背包变量**（不是用一次就写一次，也不是不扣）。
2. **栏位归属**：**每个我方单位各 3 个**（契约者 3 + 每个队友各 3）。敌方没有。

### 21.2 变量路径（权威 schema 查证，不需要再问）

### 21.6 施工中发现并修掉的**既有重伤**：`资源` 动作的基准单位算错了

做药水时踩到的 —— **不修的话，快捷物品栏做出来就是坏的**（喝药水会把血设成 20）。

**病灶**（`combatInterpreter.执行动作` 的 `case '资源'`）：它拿
`来源.资源[名] || 0` 当基准算出**绝对值**。而对 HP/MP/耐力 来说
`来源.资源['HP']` **永远是 undefined**（真实血条在 `单位.HP_当前`，不在资源池里）。于是：

| 卡面/提示词的写法 | 实际发生的事 |
| :--- | :--- |
| 「恢复 50 点 HP」 | `0 + 50 = 50` → 落效果把 HP **设成 50**（不是 +50；满血肉盾反而被削） |
| 「每回合抽离 8% 最大HP」 | `max(0 − 量, 0) = 0` → 落效果把 HP **设成 0 —— 当场打死** |
| 「给队友回血」 | `执行规则` 的"来源"是**施法者** → 连基准单位都拿错了 |

**修法**：`执行动作` **只记「名 + 操作 + 量」**（新类型 `资源变动`），
绝对值交给 `落效果` **按每个落点单位自己的当前值**算（同一批里对同一字段的多次变动按顺序累加）。
两处消费者（`combatInterpreter` 产出 / `loop.落效果` 消费）各改一处，形状干净。

**仍未修（另开话题，别顺手改）**：表达式标识符（`最大HP` / `防御` / `闪避` / 各属性修正…）
取的是**施法者**的值，不是目标的 —— 所以「抽离目标 8% 最大HP」现在按**施法者的最大HP**算。
这一条要动 `求值` 的来源口径，会牵动所有既有配方，得单独立项。

### 21.7 玩家修正（2026-10-11，当天）：快捷物品**不是**特殊资源

玩家原话：
> 「nonono，快捷物品不要放进"特殊资源"啊，特殊资源是单指那些层数、状态、施法的资源等等。
>   快捷物品在角色详情下面单开一行吧，列出可使用的快捷物品，和对应的效果，以及剩余数量。
>   数量为 0 也不归零。」

**我第一版做错了**：把剩余数量灌进了 `单位.资源`，于是它显示在单位卡的「资源:」那一行、
还会被 `写回战斗结果` 一起写进卡面的「特殊状态栏」。改：

| | 改前 | 改后 |
| :--- | :--- | :--- |
| 存哪 | `单位.资源[物品名]` | **`单位.快捷物品[物品名]`**（新字段，types.ts） |
| 显示 | 混在单位卡的「资源:」一行 | **各自的**一行：单位卡「快捷物品:」+ 角色详情单开一块，**列出名字 / 效果 / 剩余数量** |
| 写回卡面 | 会被写进「特殊状态栏」（**错的**） | 只写背包（`写回背包消耗`）—— 已加测试钉死不许漏进特殊状态 |
| 效果 | —— | 从技能表按 `解释.物品消耗` 回捞 `效果预览`，列在名字下面 |
| 归零 | —— | **剩 0 也照列**（`快捷物品展示` 按**键**过滤，不按数量），显示「绷带 ×0（用完了）」 |
| 「资源变化时」 | 用掉物品会唤起它 | **不唤起**（快捷物品不是资源，不该唤起"攒够 5 层愤怒"那类规则） |

**仍未处理（留给玩家定夺）**：卡面 schema 有 `.transform(pickBy(数量 > 0))` ——
**背包里的物品数量一旦写到 0，下次读回来就会从背包里消失**（卡面的口径，不是战斗脚本的）。
如果玩家要的是"背包里也一直留着 ×0"，那得另想办法（schema 不在本仓库）。
