# 战斗脚本 · 行动选项与额外行动回合 — 实施计划

日期：2026-10-07
范围：`src/wxhl-combat/`
来源：玩家四条反馈（装备主动效果入行动选项 / 次要行动副武器攻击 / 行动选项效果预览 / 额外行动回合）

---

## 0. 先回答一个问题：现在有「当场打断、选额外行动」吗？

**没有。** 现状三处事实：

| 事实 | 位置 |
| :--- | :--- |
| `结算行动` 返回 `待决: 待决点[]`，但**恒为空数组**（注释明写"引擎只把结果算出来"） | [loop.ts:727](../../../src/wxhl-combat/engine/loop.ts#L727)、[loop.ts:742](../../../src/wxhl-combat/engine/loop.ts#L742) |
| `战斗状态.待决` 永远是 `null`；`待决点` 的打断/防御/转阶段/濒死四类**没有任何消费方**，`判定转阶段` 只被测试调用 | [types.ts:231](../../../src/wxhl-combat/types.ts#L231)、[turn.ts:94](../../../src/wxhl-combat/engine/turn.ts#L94) |
| 一回合是**一次性跑完**的：`跑一个回合(状态, 我方行动, 意图列表)` 内部按先攻把全部单位（含敌方意图）走完才返回，中途没有回到玩家输入的出口 | [loop.ts 跑一个回合](../../../src/wxhl-combat/engine/loop.ts) |

因此"技能给额外行动次数 → 当场打断 → 选额外行动"这条链路**需要新建**：回合驱动要拆成可暂停/可恢复的状态机，`待决点` 要真正接上 UI。

## 1. 四条反馈与目标口径

| # | 反馈 | 目标 |
| :--- | :--- | :--- |
| A | 装备主动效果没有行动类型，进不了行动选项 | 装备/道具的**主动**效果一律成为行动选项；翻译没给行动类型时**默认免费行动**；**冷却默认 1 回合** |
| B | 次要行动要有副武器攻击；没武器就不能攻击 | 次要行动列「副武器攻击」（已有）；**主武器攻击也加门禁**——没装备主武器就不给这条 |
| C | 行动选项看不出具体效果（例：二阶段变身技能不知道能干什么） | 选中选项后**立刻看到人话效果预览**：触发点、目标、数值修正、施加的状态/词条、形态切换、追加攻击、范围、条件分支 |
| D | 技能能创造额外回合/额外行动次数 | **一个额外行动回合 = 一整套行动槽**（多一个主要、次要、移动、反应；免费不限次），且**当场打断**：本回合内该单位行动走完 → 立刻再走一个行动回合。两种写法都要支持 |
| E | 反应动作选了完全没用、也不实现 | 反应动作**真正结算**：被攻击时用反应技能（防御判定/护盾/减伤/反伤/打断），扣反应槽、吃冷却 |
| F | 预设的六个反应动作（击溃/识破/招架/闪避/格挡/闪烁）不该存在 | 取消硬编码列表；**只有学过、且行动消耗=反应动作的技能**才能选，没学就没有 |
| G | 单位回合内行动顺序要能自己定（buff 不能排在大招后面） | 一个单位本回合的多个行动**顺序由玩家指定**（含移动），引擎按指定顺序结算 |

## 2. 设计

### 2.A 行动类型归一化（反馈 A）

新增纯函数 `规范行动消耗(解释) → '主要行动' | '次要行动' | '免费行动' | null`（`engine/actionOptions.ts`）：

| 输入 | 输出 |
| :--- | :--- |
| 类型含 被动 / 光环 / 制造系 | `null`（不是行动，被动数值效果照旧走 `常驻修正`） |
| 行动消耗 = 主要行动 / 次要行动 / 免费行动 | 原样 |
| 行动消耗 = 无 / 空，且类型是**主动**（主动 / 辅助 / 其他非被动） | `免费行动` ← **本次新增的兜底** |
| 行动消耗 = 无 / 空，且类型也缺 | `null` |

- `可主动使用` 改为基于它实现，`列行动选项` 用它归类，**免费行动**照旧进多选区（不限次）。
- 冷却：`冷却回合数` 已经默认 1，且冷却门禁在槽位检查**之前**（[loop.ts:881](../../../src/wxhl-combat/engine/loop.ts#L881)），对免费行动同样生效 → 免费行动**不是无限连放**，同一技能仍受冷却约束。**这一点写进测试钉死**。
- 翻译提示词（`ai/skillInterpreter.ts`）补三条：装备/道具的**主动**效果必须给 `行动消耗`；卡面写「即时」→ `免费行动`；实在没写 → `免费行动`。被动/常驻效果仍写 `无`。

### 2.B 基础攻击（反馈 B，按裁决修订）

- 玩家口径（最终）：「没武器就放技能或者徒手攻击嘛，怎么都行」→ **不做门禁**，但**标签要诚实**：
  - 主要行动：有主武器 → 「主武器攻击（武器摘要）」；没有 → 「徒手攻击（徒手 1d4 · ×0.5）」。
  - 次要行动：有副武器 → 「副武器攻击（…）」；没有 → 「徒手攻击（徒手 1d4 · ×0.5）」。
  - 免费行动：不列基础攻击（不变）。
- 引擎侧 `基础攻击解释(有武器?)` 的徒手兜底**保留**（敌方 AI 没武器时仍能出招，不再回到"敌人不出招"）。

### 2.C 效果预览（反馈 C）

新模块 `engine/effectPreview.ts`，纯函数（有测试）：

```ts
效果预览(解释) → {
  头部: string[]        // ['免费行动', '自身', '无伤害', '冷却1']
  行: string[]          // 规则人话：'使用时 → 对攻击目标：施加状态「二阶段·觉醒」3回合；STR修正+50；攻击倍率+1'
}
```

- 覆盖全部 `动作` 分支：资源 / 护盾 / 数值修正 / 施加状态 / 词条 / 领域 / 切换形态 / 追加攻击 / 范围伤害 / 条件分支 / 规则系判定。
- `取值`（量）人话化：常数 → `+50`；`源 + 系数` → `防御×0.3`；表达式 → 原样。
- `条件` 人话化：`HP比例 < 0.5` → `自身HP低于50%时`。
- `engine/viewModel.ts` 的 `造技能展示` 增加 `预览` 字段；`BattleView.vue` 在每个槽（主要/次要）+ 免费多选区下方，渲染**已选中项**的预览卡（未选不显示，避免刷屏）。单位详情面板的技能表也用它。

### 2.D 额外行动回合 + 当场打断（反馈 D）

**语义**（按玩家口径"多一个回合的本质是多一倍的行动槽"）：

- 新增 `数值修正目标`：`额外行动回合`（量 = 次数）。
- 落成状态 → 单位获得 `追加行动` 计数（放状态里，`数值修正.额外行动回合`，与现有通道一致）。
- **一次额外行动回合 = 一整套行动槽**：`行动槽重置` 再给一套（主要+1、次要+1、移动+1、反应+1；免费不限次），并**再给一份移动额度**（`回合开始额度`）——没有额度，多出来的移动槽没有意义。
- 追加行动回合**不**重跑阶段A（冷却不在追加回合里递减）、**不**重跑阶段F；阶段F 在整轮（含全部追加回合）末尾结算一次。

**打断与恢复**（本次的架构改动）：

`loop.ts` 拆成三个层次，老函数保留：

1. `开一轮(状态, 我方行动, 意图列表) → { 状态, 顺序, 游标 }` —— 归一化行动表/意图，建立先攻序列，不动任何结算。
2. `走一步(轮) → { 轮, 步骤, 待决 }` —— 结算**下一个**单位的**下一个**行动；若该行动让行动者获得 `追加行动`，返回 `待决点 { 类: '额外行动回合', id }` 并**停在这里**。
3. `跑一个回合(...)` = `开一轮` + 循环 `走一步` 直到无待决且走完 —— **现有测试与调用方零改动**。

`待决点` 新增一类：`{ 类: '额外行动回合'; id: string }`。

**追加回合只属于我方**（玩家口径：「追加回合敌人不出招，是玩家自己的追加回合；这一整个行动轮敌人照常出招，只是玩家的行动槽多了一倍」）：

- 追加行动回合**只对获得它的我方单位**开放；敌方**不参与**追加回合，仍在本轮先攻序列里照常出招一次。
- 因此追加回合**不需要**再调一次敌方意图生成（省一次 AI 调用，也贴合"敌人不会凭空多一个回合"）。

`CombatView.vue` 的新流程（轮次不再是"填一次跑一轮"）：

```text
推进回合（阶段A/冷却/意图生成，不变）
  → 玩家填写 → 开一轮
  → 循环 走一步：
      待决 = 额外行动回合 ?
        我方 → 弹出「追加行动」：BattleView 只为该单位启用填写区（槽位是重置后的新一套），
               玩家提交后 走一步 继续（原序列里还没走完的单位照旧按先攻继续）
        敌方 → 不会产生这个待决点（追加回合只属于我方）
      : 继续走
  → 全部走完（含追加回合）→ 阶段F → 判战局（不变）
```

**防跑飞**：每个单位每回合追加回合上限 5（超出记日志忽略）；`追加行动` 计数每次消耗 1，用完为止。

### 2.E 反应动作真正结算（反馈 E）

现状：反应下拉的取值只被拼进一句日志（`（已预置反应：契约者：招架）`，[CombatView.vue:470](../../../src/wxhl-combat/views/CombatView.vue#L470)），**没有任何结算路径读它**；`待决点` 的 `打断`/`防御` 两类没有消费方。反应槽也从未被扣过。

本次接上，复用 §2.D 建好的"暂停/恢复"基础设施：

- **预置即自动**：玩家在本回合为每个单位预置一个反应技能（或不预置）；被攻击时**自动**用预置的那个，不再弹窗（保持战斗节奏）。没预置 = 不反应。
- **两个时机产出待决点**（对预置了反应的守方）：
  1. **命中判定前** —— 技能带约定词条 `打断`（击溃/识破这类）：打断检定 = `1d20 + 对应属性修正×3/4（下取整）`，**劣势**（掷两次取低），与攻方命中检定对抗；成功 → 本次攻击取消；失败 → 攻击照常结算，且攻方本回合对该守方命中 +2（世界书原文）。仅可打断**可预判**攻击。
  2. **伤害结算前** —— 防御判定类（招架/格挡/闪烁）与护盾/减伤/反伤类：按该技能 `规则` 里现成的动作结算（`数值修正 减伤` / `护盾` / 条件分支 + 反伤），无需新动作类型。
- **消耗**：反应技能扣 1 反应槽、按 `冷却回合数` 进冷却、按 `消耗` 扣 MP/耐力（与主动技能同一套门禁）。
- **敌方反应**：和玩家同一口径 —— **有预置就自动用，没预置就跳过**（AI 意图生成时为敌方标注预置的反应技能；随机模式由 `随机意图` 顺带 roll 一个），**不额外调 AI、不弹窗**。
- 单位每回合的反应槽仍由 `回合开始行动槽` 给（含 `反应动作` 数值修正目标）。

### 2.F 取消预设反应列表（反馈 F）

判定依据是技能的**行动类型**，不是资源消耗：

- 「行动类型」= 翻译结果里取值 `主要行动 | 次要行动 | 反应动作 | 免费行动 | 无` 的那个字段。
  **注意字段名**：代码里这个字段现在叫 `行动消耗`（历史起名，容易和资源消耗混），
  本次顺手在类型注释与提示词里统一叫「行动类型」，**字段名暂不改**（改了要动全部翻译缓存与既有测试）。
- 「资源消耗」是另一个字段 `消耗`（`MP 5` / `耐力 8`），**与判定无关**。
- 删掉 [BattleView.vue:348](../../../src/wxhl-combat/views/BattleView.vue#L348) 的 `反应选项 = ['击溃','识破','招架','闪避','格挡','闪烁']`。
- 改由 `列行动选项(u, '反应动作')` 提供：**只列该单位技能表里行动类型 = `反应动作` 的技能**（`规范行动消耗` 同步支持这一类型，被动/光环仍然排除）；没学过 → 下拉里只有"不预置"。
- 翻译提示词补：反应类技能（卡面写"反应动作/招架/格挡/打断"这类）行动类型必须填 `反应动作`；打断类（击溃/识破这种取消攻击的）额外加约定词条 `打断`。约定词条与 `连击`/`免冷却` 同一机制（引擎直接检查，不过判定）。

### 2.G 回合内行动顺序可自定（反馈 G）

- `行动槽填写` 新增**可选**字段 `行动顺序?: string[]`，元素为 `'主要'` / `'次要'` / `'免费:<技能名>'` / `'移动'`。`构造行动声明` 有它 → 按它产出行动数组；没有 → 保持今天的固定顺序（主要 → 次要 → 免费 → 移动），**旧测试与旧调用零改动**。
- 引擎侧**不用改**：`跑一个回合` 本来就是按给定数组顺序逐个结算（`for (const 行动 of 本行动)`），顺序即玩家意图。
- `BattleView.vue`：主要/次要下拉 + 免费多选 + 移动输入 之外，加一个**本回合行动顺序**列表——把已选项合成有序列表，每条带 ↑/↓ 调序；默认按现有固定顺序排列。免费行动由"勾选"改为"可多次添加的条目"，才能与主要/次要交错排序。
- 顺序不影响槽位门禁：每个行动照旧扣各自类型的一个槽（主要扣主要、次要扣次要、免费不扣）。

## 4. 实施步骤（每步 TDD：先写失败测试）

1. **规范行动消耗 + 装备主动入选项**（A）：`modifierTargets`/`actionOptions` 测试；反向验证（把兜底去掉 → 装备主动效果消失，测试红）。
2. **主武器门禁**（B）：有/无主武器两种断言。
3. **效果预览**（C）：`effectPreview` 全动作类快照测试（含二阶段变身：切换形态 + 施加状态 + 数值修正三件套）；`renderViews` 渲染守卫。
4. **反应技能可选项 + 删预设列表**（F）：只列 `行动消耗=反应动作` 的技能；断言硬编码六项**不再出现**（反向验证：改回硬编码 → 测试红）。
5. **回合内行动顺序**（G）：`构造行动声明(填写, 目标)` 带 `行动顺序` 时按之产出；不带时与今天逐字相同（旧测试不动）；顺序影响结算先后（断言"先上 buff 再放大招"与"先放大招再上 buff"的伤害不同）。
6. **额外行动回合：落效果 + 槽位倍化**（D1）：纯函数层 —— 用了给 `额外行动回合` 的技能后，再走一步时该单位槽位是重置后的一套。
7. **额外行动回合：打断**（D2）：`走一步` 返回待决点；`跑一个回合` 在有待决时**不**把后续单位跑完（反向验证：断言"序列表里后面的单位还没动"）。
8. **反应动作真正结算**（E）：打断检定（劣势、×3/4、成功取消攻击、失败命中+2）；防御类按规则减伤/护盾/反伤；扣反应槽 + 进冷却 + 扣资源；没预置 = 不反应。
9. **状态机接进 UI**（D3/E4）：`CombatView` 轮次循环 + 追加行动面板 + 反应待决；`renderViews` / `viewScriptScope` 守卫每步跟着改。
10. **提示词与文档**（A/D/E/F）：翻译提示词补三处口径；设计文档（`docs/superpowers/specs/2026-10-06-wxhl-combat-engine-design.md`）追加一节。
11. **全量回归**：`npx vitest run`（当前 1624 用例）、`npx tsc --noEmit`（基线 44）、`npm run build`、`bash scripts/push-combat.sh`。

## 5. 验收标准

- 一件带主动效果的装备（如天基.txt 里的空间宝石）出现在**免费行动**多选区里；点了有用、且**同一技能受冷却约束**。
- 一把没装备主武器的单位，主要行动下拉里**没有**"主武器攻击"；装了副武器才出现"副武器攻击"。
