## 🔴 最高风险先测这三项

### ① 生成副本会不会直接失败

点「🎲 掷骰」→「生成副本」。

**为什么先测它**：发给 AI 的 JSON schema 是用 `z.toJSONSchema()` 生成的，而 `aiGenerate` 会带 `strict: true`。如果它生成的 schema 缺 `additionalProperties:false` 或 `required` 不全，**OpenAI 系端点会直接 400**，你会看到一条难懂的网络报错。

同文件的既存 `INFLUENCE_SCHEMA` 是同样的形状且线上跑得通，所以大概率没事——但这是**唯一一个"可能一上来就不能用"的点**。

- ⬜ 生成成功
- ⬜ 若失败：把 Console 里的**原始报错**发我。兜底方案是改用手写 schema（约 20 行）

### ② 写入存档到底有没有写进去

点「写入存档」，然后在 Console 里跑：

```js
const v = getVariables({ type: 'message', message_id: -1 })
console.log(JSON.stringify(v.stat_data.契约者.当前副本元数据, null, 2))
console.log(JSON.stringify(v.stat_data.契约者.当前副本任务, null, 2))
console.log(JSON.stringify(v.stat_data.契约者.固有角色名单, null, 2))
console.log(JSON.stringify(v.stat_data.契约者.其他契约者名单, null, 2))
```

- ⬜ 四个键都有内容（不是 `undefined`、不是空对象）
- ⬜ `当前副本元数据.基准等级` = 你当前的等级
- ⬜ 主线/支线的 `奖励` 数值与掷骰面板上显示的奖励骰**逐一对得上**
- ⬜ 成就的 `难度` 形如 `★ 探索级 · …`（**不是** `★ 探索级 · ★ 探索级`）
- ⬜ 称号为「无」的契约者在名单里是 `无称号`
- ⬜ **先记下写入前 `契约者.小队` / `背包` / `装备` 的快照，写入后对比没变**

> 这一版**新增了写入后回读校验**：如果键名与你的存档 schema 对不上，现在会直接弹错误而不是静默成功。所以「弹了成功」就意味着真的写进去了。

### ③ 手机端能不能填进输入框

点「填入输入框」。

- ⬜ 桌面视口下：酒馆输入框出现进本提示词，且**没有被自动发送**
- ⬜ **切到手机视口再测一次**（或直接用手机端酒馆）

**为什么**：脚本用的选择器是 `#send_textarea`，主路径失败才回退 `/setinput`。手机端酒馆的 DOM 可能不同。

- ⬜ 若都失败：把 Console 报错发我
