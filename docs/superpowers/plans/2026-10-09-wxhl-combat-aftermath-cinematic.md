# 战斗收尾正文 · 电影感改造 — 实施计划

日期：2026-10-09
范围：`src/wxhl-combat/`（收尾提示词的**输入**与**口径**；不改战斗引擎的结算逻辑）
玩家反馈原文：

> 战后结束的提示词还是有问题，我刚刚试了一下完全没有美感，只是对战斗日志的复述。
> 应该把**环境、角色构筑**什么的都发给模型，让模型理解**是什么技能、产生什么效果**，
> 而不是复述行动名字。要有**电影感、小说感**。

## 0. 根因（为什么现在读起来像复述）

| # | 现在喂了什么 | 后果 |
| :--- | :--- | :--- |
| 1 | **只有战报**（`结算步骤.内容` 拼起来的日志） | 日志里是"技能名 + 数字"（`「苟或」的「龟派气功·超绝」命中…`），模型**不知道龟派气功是什么**，只能把名字与数字换个说法重说 |
| 2 | **没有环境** | 战斗脚本从来没读过卡面的场景，也没有上一楼正文 —— 模型无景可写，只能写"他打了他" |
| 3 | 提示词第 4 条写着「**不要自己加战报里没有的**」 | 这条**主动禁止**了环境、感官、动作细节、内心 —— 于是"不写与战报无关的"就等价于"只复述战报"。它本来是为了防编造结果，却把文学性一起禁掉了 |

## 1. 三条已裁决（玩家口径）

1. **环境的来源**：「把模型输入的开战前的上一楼正文发过来呗」→ 读酒馆里**开战那一刻的上一楼正文**（模型当时的输入），随战斗快照一起存下来（打十几轮后楼层被顶走也拿得到）。
2. **角色构筑发多少**：**只发战报里真正用到的**技能/装备/状态 + **双方构筑摘要**（含职业/血统/天赋/称号名与装备清单）。
3. **事实边界**：**结果不许改，画面可自由写**——命中/伤害/生死/掉落/胜负必须与战报一致；环境、光影、声音、动作过程、内心一闪由模型自己写，但不得与战报冲突。

## 2. 设计

### 2.1 输入从「一份日志」变成「五段」

```
【开战前的上下文】  ← 新增：开战那一刻的上一楼正文（截断到 3000 字）+ 开场距离模式
【参战者】          ← 新增：双方摘要（谁、什么类型/阶位、HP 上限、防御/闪避、装备、职业/血统/天赋/称号、开战时状态）
【用到的技能与效果】← 新增：战报里出现过的效果，逐个附**人话效果**（复用 engine/effectPreview）
【战斗战报】        ← 保留（引擎逐条记下的实况，作为"结果的事实来源"）
【击杀与掉落】      ← 保留（钥匙清单）
```

**为什么"只发用到的"就够**：模型不需要通读整张卡，只需要理解**这一场里出现过的那几个**技能。效果人话我们已经有现成的（`效果预览`）：

```
崩玉神化之痕（头部）｜类型 被动｜常驻 → 自身：防御 +3、闪避 +15
龟派气功·超绝｜主要行动｜伤害 ×7.75｜冷却 3｜消耗 MP 150｜使用时 → 攻击目标：伤害 +200%
```

### 2.2 叙事口径（替换现在的第 4 条与风格段）

- **不许改结果**：命中/未命中、伤害量级、谁倒下、掉落、胜负 —— 与战报一致；**不许为了好看把未命中写成擦伤**。
- **画面自由写**：环境、天气、光线、声音、味道、动作细节、对手的反应、角色内心一闪 —— 你来写。
  战报没写的**过程**可以补，但**不能与战报冲突**。
- **技能必须"讲清楚做了什么"**：技能名可以出现，但每次都要用旁白交代它**做了什么、造成了什么结果**
  （例：「黑棺」——四面黑色立方体合拢，内部压力在一瞬间撕碎了目标的外壳）。不许只念名字，也不许写成规则条文。
- **电影感的具体要求**：镜头跟着交手走（谁先动、刀锋落在哪、护盾碎在哪一刻、距离怎么被拉开又逼近）；
  数值用文学化表达（"那一击压得他掉了半条命"），**不写骰值与公式**。
- 仍然不写：规则说明、预告式结尾、微表情八股。

### 2.3 数据来源

| 新输入 | 来源 | 备注 |
| :--- | :--- | :--- |
| 上一楼正文 | `getChatMessages(-1, { role: 'assistant' })`；若最后一楼是玩家发言则往前找 2~3 楼；都取不到就退到"最后一条消息" | 开战时读一次，**存进战斗快照**（`engine/persist`），收尾时取用 |
| 开场距离模式 | `开始战斗` 已有的 `开场模式`（对峙/室内…） | 现在只写进日志，改成结构化传给收尾 |
| 参战者摘要 | `战斗单位`：名称/类型/阶位/HP 上限/防御/闪避/主副武器/`装备`/`状态`/`词条` | 血统/天赋/职业特性在我们的 `技能` 表里就是条目名（`赛亚人·远古血脉（血统）`），列出名字 + 一行摘要即可 |
| 用到的效果 | **从战报里扫**出效果名（`「…」` 里的名字，排除单位名），到 `单位.技能` 里查解释 | 纯函数、可测；查不到的（模型瞎编的技能名）不列 |
| 效果人话 | `engine/effectPreview.效果预览(解释)` | 复用，不新增维护点 |

## 3. 实现步骤（每步 TDD）

1. **纯函数**（`ai/aftermath.ts` 或新 `ai/aftermathInput.ts`）：
   - `从战报提取用到的效果(步骤, 单位表)` → `{单位, 效果名, 人话}[]`（扫中文引号、去重、排除单位名、查不到的跳过）
   - `构筑摘要(单位)` → `string[]`（类型·阶位·HP·防御/闪避·武器·装备·职业/血统/天赋/称号·开战时状态）
   - 单测：引号里的名字要能分辨"单位名 vs 技能名"；重复出现只列一次；装备/血统名带括号后缀也要认
2. **持久化**：`engine/persist` 快照加 `开战前上下文?: string` 与 `开场模式?: string`；**向后兼容**（老存档没有 → 空；测试钉住）。
3. **读取**：`store.读上一楼正文()`（`getChatMessages` 取值 + 截断 + 出错返回空串）；`CombatView.开始战斗` 调用并存入快照。
4. **提示词**：`构建收尾提示词(步骤, 状态, 额外)` 加三段输入 + 换 §2.2 口径；无上下文时明确写「（无 —— 按战报与参战者信息写）」。
5. **接线**：`写收尾楼层(步骤, 状态, 额外)` 传参；`CombatView.收尾` 从快照/内存取。
6. **测试**：提示词内容断言（五段都在；"用到的技能"人话在；**没用到的不在**；事实边界两句都在；无上下文不崩）。
7. **回归**：`npx vitest run` / `tsc` / `npm run build` / `bash scripts/push-combat.sh`。

## 4. 新提示词骨架（草案，供你先看形状）

```

【开战前的上下文】（这是开打之前发生了什么 —— 环境、气氛、局势都从这里长出来）
<上一楼正文，截断到 3000 字>   ＋（开场：对峙 / 室内，双方距离 12 米）

【参战者】
▸ 青空黎（玩家 · 三阶）HP 上限 420 · 防御 22 · 闪避 31
   装备：斩魄刀·镜花水月（主武器）、纯白长摆战袍（下装）…
   职业/血统/天赋：「维度超越·立于顶峰」（天赋）、「赛亚人·远古血脉」（血统）…
   开战时状态：无
▸ 乌尔奇奥拉·西法（BOSS · 四阶）HP 上限 4180 · 防御 130 · 闪避 271
   装备：…
   职业/血统/天赋：超速再生（血统）…

【用到的技能与效果】（引擎逐条翻译过：理解它做了什么，再写出来 —— 不要只念名字）

    使用时 → 攻击目标：伤害 +200%
- 「黑棺」（乌尔奇奥拉·西法）｜主要行动｜伤害 ×5｜冷却 3
    使用时 → 攻击目标：施加状态「封锁」2回合
- 「超速再生」（乌尔奇奥拉·西法）｜被动
    回合开始 → 自身：HP 设为 最大HP

【战斗战报】（引擎逐条记下的实况：先攻顺序、每一击的命中与否、六步伤害、护盾与减伤、
状态与冷却、掉落。**结果以它为准**）
<战报>

【击杀与掉落】（严格按这份清单写）
- 骨卫兵（精英）→ 获得 白银钥匙 ×1

【怎么写】
1. **结果不许改**：命中/未命中、伤害量级、谁倒下、掉落、胜负 —— 与战报一致。不许为了好看改写结果。
2. **画面自由写**：环境、天气、光线、声音、动作细节、对手的反应、角色内心一闪 —— 你来写。
   战报没写的过程可以补，但**不能与战报冲突**。
3. **技能要讲清"做了什么"**：技能名可以出现，但每次都用旁白交代它做了什么、造成什么结果。
4. **电影感**：镜头跟着交手走 —— 谁先动、刀锋落在哪里、护盾碎在哪一刻、距离怎么被拉开又逼近。
   数值用文学化表达（"压得他掉了半条命"），**不写骰值与公式**。
5. **完整**：每次交锋都要写到；篇幅不限，但不重复、不凑字数。
6. 结尾交代结果与钥匙；不写规则说明、不写预告式收尾。

【风格】客观冷静，白描为主；世界对契约者绝对中立；死亡廉价，不美化；只写正文。
【示例笔法】<保留现在的示例>
```

## 5. 待你确认的两个默认（我按建议先写进计划）

1. **上一楼挑哪条**：默认取**最后一条 assistant 消息**（多数情况就是开战前的叙事）；如果它其实是玩家自己的发言，往前找最多 3 楼；都取不到就不写这一段。
2. **上下文长度**：默认截断到 **3000 字**（超出截尾并标注）。太短会丢气氛，太长会把提示词顶大。

## 6. 不做

- 不改战斗引擎的结算与胜负判定（这次只动收尾的输入与口径）。
- 不去读卡面的「场景/主线任务」变量（你选了"上一楼正文"，那条更贴现场）。
- 不为了戏剧性改动结果（§1.3 已裁决）。
