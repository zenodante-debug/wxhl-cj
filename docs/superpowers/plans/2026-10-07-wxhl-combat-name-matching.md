# 战斗中中文名字适配 —— 计划与解决措施

日期：2026-10-07
范围：`src/wxhl-combat`（独立战斗脚本）
等级：**bounded**（对现有代码的有界修改：新增一个纯函数模块 + 改两处名称解析 + 提示词硬化；不新建子系统、不碰 MVU 变量层）

---

## 1. 问题

玩家实测：快路 AI 生成**敌方意图**时会把名字里的汉字替换成**注音符号**。

```text
本尊（MVU 变量里的键，正确）：工蜂异形幼体
模型在意图里写的        ：工蜂异形ㄧㄡˋ体     ← 幼 → ㄧㄡˋ（注音，4 个字符）
```

后果：意图里的 `单位` / `目标` 对不上战场上的任何单位 → `找单位` 返回 `undefined` →
该行动被跳过（`跳过：「X」的目标「工蜂异形ㄧㄡˋ体」不在战场上`），表现成
**「无法识别目标的意图」**：敌人站住不动，或行动被静默丢弃。

### 已确认的事实（决定了边界）

- **名单是好的**（玩家确认）：坏名只出现在**意图 / 跳过日志**里，MVU 变量里的键是正确的。
  → 坏源是**快路模型的输出**，不是变量层。**不触碰 MVU 变量写入侧，不做数据修复。**
- 全项目**只有两处**在按中文名比对：

  | 位置 | 比什么 | 现有容错 |
  | --- | --- | --- |
  | `engine/loop.ts` 的 `找单位` | 意图里的**单位 / 目标** | 只有精确匹配（键 / id / 「玩家」特判） |
  | `engine/loop.ts` 的 `匹配技能名` | **技能名** | 只剥装饰（引号/书名号/空白），**拒绝模糊** |

  其余（翻译结果、写回变量、状态名）都按 **id / 编号** 走，不受影响。
- 这类坏**不可能靠"更严格的精确匹配"解决**，只能：① 让模型别写坏（防治），② 认得出并纠正（容错）。

### 为什么 `幼 → ㄧㄡˋ` 是"替换"而不是"夹注"

字符串是 `工蜂异形` + `ㄧㄡˋ` + `体` —— **原来那个「幼」已经不在了**。
所以「把注音删掉」得到的是 `工蜂异形体`，**不等于** `工蜂异形幼体`（少一个字）。
把注音还原成汉字在原理上做不到（`ㄧㄡˋ` 对应 幼/又/右/佑/侑/宥/诱… 一对多）。

→ 结论：**先用"去注音"把距离拉近，再用"候选集内唯一最近似"把它绑回去。**
`工蜂异形体` 与 `工蜂异形幼体` 的编辑距离是 **1**（插入「幼」），相似度 ≈ 0.83；
而 `工蜂异形ㄧㄡˋ体` 与 `工蜂异形幼体` 的距离是 **3**，仅 0.625 —— 不去注音就够不着阈值。

## 2. 解决措施

四层，按"性价比"排序；**M1 + M2 + M3a + M4 是本次要做的**，M3b 是可选加强项。

### M1 · 名称归一化统一入口（纯函数，新模块 `engine/nameMatch.ts`）

`归一化名(名: string): string`，按顺序：

1. `String.normalize('NFKC')` —— 全角→半角、兼容字符归位（`Ａ`→`A`、`１`→`1`、全角括号→半角）
2. 去掉所有空白（含 U+3000 全角空格）
3. 去掉装饰：`「」『』【】《》〈〉“”‘’"'`（）()[]{}·、,，。:：!！?？~～-—_/\`
   （与现有 `归一化技能名` 同一套，**合并成一个实现**，避免两套规则漂移）
4. **去掉注音残留**：注音字母块 `U+3105–U+312F`（`ㄅ`–`ㄩ`）+ 注音调号 `U+02C7/02CA/02CB/02D9`

**不做繁→简字典**（YAGNI）：繁简差异通常是 1–2 个字的**替换**，交给 M2 的近似层就能跨过
（`體`↔`体` = 1 次替换）；全繁体名字会落在阈值之下 → 走"拒绝 + 报候选"，**不会误绑**。
引入 `chinese-simple2traditional` 或走 CDN 都要付出打包体积 / 运行时失败模式，
等诊断日志证明真的出现再说。

**不做无脑删拉丁字母**：名字可能本来就含字母数字（`T-800`）。注音块与调号是安全的删法。

### M2 · 候选集内**唯一**最近似绑定

把 `找单位` / `匹配技能名` 统一改成走 `解析名字引用(候选: 名字[], 引用: string)`，三层：

| 层 | 规则 | 行为 |
|---|---|---|
| 1 | 精确（键 / id / 「玩家」特判） | 命中即用（**现有行为，不变**） |
| 2 | 归一化后精确（两侧同归一） | 命中即用 |
| 3 | **近似唯一** | 见下 |

第 3 层的门槛（全部满足才绑）：

- 相似度 = `1 − 编辑距离 / max(len)`，在**归一化后**的串上算，**只在战场候选集内比较**（不做全局模糊）
- 最佳相似度 **≥ 0.75**
- 最佳 − 次佳 **≥ 0.15**（第二名差得远 = 只有一个人选）
- 归一化后名字长度 **≥ 3 字**（两字名太容易撞）
- 长度差 **≤ 2**

**阈值为什么是 0.75 而不是 0.8**（已用真实字符串核过）：

| 比对 | 编辑距离 | 相似度 | 结论 |
|---|---|---|---|
| `工蜂异形ㄧㄡˋ体` vs `工蜂异形幼体`（**不去注音**） | 3 | 0.625 | 够不着 → 证明"先去注音"是必需的 |
| 去注音后 `工蜂异形体` vs `工蜂异形幼体` | 1 | 0.833 | 绑得上 |
| 去注音后 vs 混淆项 `工蜂异形兵体` | 1 | 0.833 | **打平** → 唯一性判定拒绝绑定 |
| `卫兵` vs `骨卫兵` | 1 | 0.667 | 长度 2 → 直接拒 |

0.8 会把「4 字名字错 1 字」（= 0.75）一并拒掉 —— 那正是最常见的形态。
0.75 的语义是"**每 4 个字允许错 1 个字**"，配合"唯一领先 0.15"这道闸就已经够安全。

第 3 层的门槛（全部满足才绑）：

**两个实现陷阱（必须写进代码）**：

1. **候选要按"单位"去重，不能把别名摊平成候选串**。一个单位有键 / 全路径 id / 显示名三个别名，
   若把三条都塞进候选集，它自己就会和自己打平（差距 0 < 0.15）→ **永远拒绝绑定**。
   正确做法：每个单位先取"它最能匹配的那个别名"作为该单位的相似度，**唯一性在单位之间比较**。
2. **相似度只在归一化后的串上算**。忘了归一化 = 注音没被删 = 距离回到 3 = 救不回来。

**拒绝比错绑好**：不满足就返回"未找到"，并把 **前 3 个候选 + 相似度**写进日志。
拒绝的代价是"该单位本回合空过"（可见、可重跑），错绑的代价是"打了别人"（不可见、且违反引擎当裁判的原则）。

为什么加"长度 ≥3 / 差距 ≥0.15"：`找单位` 的既有裁决明确禁止模糊后缀匹配
（`卫兵` 不能绑到 `骨卫兵`）。本方案的两字名直接拒、且要求唯一领先，正是为了不推翻它 ——
下面的测试清单里专门钉了这条回归。

### M3a · 提示词硬化（治本，成本最低）

在敌方意图提示词里加一段"**名字是标识符，不是文本**"：

- `"单位"` / `"目标"` / `"技能"` 里的名字**逐字照抄**，一个字都不能改
- 不要加注音（ㄅㄆㄇ）、不要加拼音、不要加括号注音、不要繁简转换、不要"顺手修正"错别字
- `"目标"` 只能填提示词里列出的我方 id 之一（现在已列出 id，再明写"只能填其中之一"）
- 不确定时**照抄原样**，不要猜、不要美化

### M3b ·（可选加强，需要你点头）单位/目标 改为"候选编号"回填

让模型返回 `"目标": 1`（我方候选清单里的编号）而不是名字 —— 模型只复制数字，
**从构造上消灭"抄坏名字"这一整类**。翻译流程已经在用"编号对号入座"，模式是验证过的。

- 好处：单位/目标这两个字段再也不受汉字适配影响
- 代价：契约变更（提示词 / schema / 解析 / 测试都要改）；且**编号填错是静默的** ——
  填错一个编号会变成"打了别人"，而名字对不上至少是**可见跳过**。技能名仍要靠 M1/M2
- 建议：**先不做**。M1+M2+M4 做完后如果诊断日志显示模型换着花样写坏名字，再上这一层

### M4 · 诊断：把现场写进战斗日志

- 绑定成功：`意图里的「工蜂异形ㄧㄡˋ体」按最近似绑定到「工蜂异形幼体」（相似度 83%）`
- 绑定失败：`跳过：意图里的单位「…」不在战场上；近似候选：A(0.83)、B(0.42)、C(0.31)`
  （单位/目标两侧都要列候选 —— 现在只对技能名列了可用技能，单位侧只有一句"不在战场上"）
- 目的：**下一次现场直接并排打出坏串与正确串**，不用再猜是哪一侧坏的

## 6. 明确不做（写下来免得以后反复讨论）

- **不做繁→简字典 / 不引入 CDN 依赖**：繁简差异交给近似层；全繁体 → 拒绝 + 报候选
- **不做无条件模糊匹配**：会打错目标
- **不碰 MVU 变量层**：已确认名单是对的
- **不做 M3b 编号化**（除非诊断日志证明模型换着花样写坏）
- **不动 `.cursor/rules` 里 `COMMAND_PARSED` 那套修复**：那是给"变量键被写坏"用的
